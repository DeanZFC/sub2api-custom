# 渠道质量管理

统一入口为管理后台 `/admin/tests`，默认打开「分组质量」，另外三个主入口为「智力检测」「事件与恢复」「更多设置」。日常只需选择保护分组并设置四个质量目标，再选择智力检测项目和执行时间。题库、预算及健康总览归入更多设置；旧规则及评分深链接返回分组质量，账号和记录定位继续有效。

每个分组只保留一个被动质量配置入口。旧版自定义规则已全部移除；不再要求另配一套“额外流量保护”。所有分组质量目标统一系统主动复测恢复，其客户试运行、可用性优先和全组应急兜底已移除；检测预算通过更多设置管理。

## 真实流量采集与准入

真实请求的指标继续独立采集，供分组质量保护、恢复和统计使用，按现有两天留存边界清理。请求开始时间在接收时记录，并随每轮请求冻结传递给异步日志任务，不从落库时间和耗时反推。

独立账号质量评分已移除，账号列表、渠道总览和检测结果不再展示质量分，也不再提供评分配置或查询接口。分组质量自动暂停阻止客户请求，自动智力暂停不能被应急兜底放行；独立统计类恢复许可仍按其自身规则判定。最终并发、利润和其他准入仍独立检查。正常 API Key 备用分组路由保持独立，只能使用通过准入的健康账号。

## 渠道状态的缓存统计与刷新

渠道状态默认汇总最近 90 分钟的成功落账用量，缓存率为 `缓存读取 Token 总量 /（输入 Token + 缓存创建 Token + 缓存读取 Token）总量`，不计输出 Token。它按完整窗口的输入量加权，不平均每笔请求的百分比；最近 20 次仅代表近期样本，少量大输入低命中请求仍可能拉低总值。渠道状态使用完整输入口径；分组保护的缓存复用证据仍按自身规则判断。

实时聚合按配置的 60 或 300 秒刷新；历史回填失败仅延后历史重试，不延后实时刷新。进程启动时重算最近两小时以修补近期缺口，统计落后时从上次成功水位分段连续追赶，每段最多两小时；完成追赶后保留最近十分钟的重算窗口，以接纳迟到的日志。历史任务按实际分段大小推进，不把较小分段扩大成整天。分段重建保留已经汇总、但原始明细超过留存期的历史数据。

页面“更新至”表示汇总的聚合截止时间；最近请求直接读取原始日志，因此可能更新得更晚。以上补算机制用于修复统计缺口，不改变缓存路由，也不把保护目标当作每次请求的缓存命中保证。最近两小时之外的既有历史缺口需要另行重算，不能仅凭水位已前进认定全部历史完整。

## 输出 TPS

质量检查、模型监控、渠道状态（含 QQ `/渠道状态`）统一展示输出 TPS，单位为 token/s。单次请求按 `输出 token × 1000 / (总耗时毫秒 − 首字毫秒)` 计算；分组、模型、时间窗口按有效请求的输出 token 总量除以生成时间总量，不平均每个请求的速率。它衡量首字之后的输出速度；原有 `TPM / 60` 继续作为“总吞吐”展示。

只使用具备有效首字计时、正输出 token 和正生成时长的文本流式请求（含 WebSocket）；图片输入后生成文本仍可计入。非流式、媒体输出、压缩、系统检测/探测、已知失败及缺失计时不进入 TPS 样本。缺少有效样本显示未知，不补零；统计口径沿用上游上报的输出 token 计数。

新建被动质量目标默认启用 TPS 下限 30 token/s，恢复阈值 36 token/s，按窗口、有效样本下限和新样本确认次数执行。TPS 与其他指标分别确认异常；主动复测必须验证所有已启用指标，首字或可用率达标不能替代 TPS 达标。统计质量检查也可选择 `output_tps` 条件，TPS 样本不足时连通性探测成功不能替代速度达标。已有目标阈值和禁用指标保持原值。

迁移 `316_channel_monitor_output_tps.sql` 为监控聚合保存分子、分母和有效样本数。已有历史聚合不会因为新增 TPS 被清空或强制重建；尚未采集 TPS 的历史区间保留未知，正常滚动聚合后开始有新数据。

## 主动智力检测与下一轮恢复

新建计划默认开启“全部自动检测通过”：当前轮任何参与自动判断的检测明确不通过，就暂停对应账号模型；定时检测继续执行，下一轮所有必需检测明确通过后解除本计划的暂停。已启用的通过率条件在这个模式下统一取最新一次有效结果（窗口 1 次、恢复连续 1 次），不再等待历史通过率回升。待执行、待复核或结果未知不会被视为通过，其他计划与被动保护的限制独立保留。

高级设置仍保留单项与组合模式及自定义题库。其近期通过率按计划、账号、题目、公开模型及规则版本独立维护，默认参数仍为 7 天内最近 10 次有效检测、低于 80% 暂停、至少 90% 且最近 2 次连续通过恢复；原有自定义参数不改写。传输错误不混入智力失败；成功返回但不满足题目输出格式算失败。

时间流逝、样本过期、重复回调、修改模型或禁用计划均不会自动解除已有暂停；显式关闭这项保护、删除规则或移除作用账号时，只清除此保护拥有的限制。既有会话和普通调度都遵守智力暂停；全组缺少正常供给也不会临时放行已暂停账号。历史结果清理不会丢失仍在生效的判断证据。

## 多模型主动检测与隔离

主动计划可一次选择 1–16 个模型，沿用同一执行时段和检测规则；每轮按“账号 × 模型 × 检测项”分别执行。鹈鹕、糖果、随机能力题和模型一致性都支持。模型选项取所选分组的共同支持范围，推理强度取全部所选模型的共同能力。旧单模型配置自动兼容。

结果、自动评审、人工复核和最近通过率分别归属于对应模型；一个模型失败只跳过该模型本轮后续检测，其他选中模型仍继续。请求与 Token 预算仍共用，多选模型会相应增加检测消耗。重试保留原模型，已从计划移除的模型不能继续重试。

主动智力保护先限制“账号 + 公开模型”。例如同时监测 A、B，只有 A 触发保护时，A 停止普通调用，B 继续；A、B 都触发保护时才暂停整个账号。待执行、待复核、证据不足不等于已确认降智。每个模型达到自己的恢复条件后独立解除限制；有一个受监测模型恢复，账号可重新正常调度，其他仍失败的模型继续禁用。所有分组都不使用受保护账号兜底。人工停用和其他硬准入仍然有效。独立统计类定时检测保护继续保留其账号级暂停、连接探测和限量试运行机制；它不属于已移除的分组质量恢复模式。

账号分组属于整个账号，部分模型失败时不会因该模型的降级动作把其他正常模型一起改组；全部受监测模型失败时才执行失败分组，全部模型满足通过条件才执行通过分组。用户结果页可选择具体模型或查看全部，分别显示账号调度和模型调度状态，历史也按模型隔离。数据库迁移 `315_scheduled_test_multi_model.sql` 为旧计划回填模型列表，并保留各模型独立的保护记录。

## 职责与数据

- `channel_quality.go` / `channel_quality_repo.go` 提供只读的账号质量视图：账号状态、人工停止、限流冷却、主动保护状态、被动保护状态与策略覆盖数量。读取总览不会调用上游或解除限制。
- 总览先按账号分页，再读取各账号的保护状态。支持账号、名称、分组、模型、异常筛选。迁移 `293_channel_quality_overview.sql` 为未暂停的主动状态补充账号索引。
- 页面拆为 `ActiveQualityPanel`、`PassiveQualityPanel`、`ChannelQualityOverview`，页面壳负责导航和定位；原因格式化复用 `useQualityLabels`。
- 账号原有状态、人工控制、主动单项与组合保护、被动策略分别拥有自己的限制。普通调度要求全部适用限制满足；所有分组不放行暂停账号，一个策略恢复不会清除另一个策略的限制。
- “未发现保护限制”只陈述当前证据；不代表模型能力已验证，也不涵盖所有余额、配额与请求兼容性准入条件。主动总览展示有保护规则的当前观测；无保护规则的历史测试仍在主动检测结果中。
- 实时保护状态与事件在服务端筛选后按游标分页，汇总卡片和各策略状态计数独立统计，不受已加载页数影响。状态按策略、账号、模型、阶段筛选；事件另支持事件类型和时间范围。暂停、受限等总览卡片按账号去重，同一账号可能同时存在多种限制。

## 分组质量目标与主动恢复

在“分组质量”中选择分组，设置缓存率、可用率、TPS 和首字 P90 目标即可启用自动保护。所有分组质量策略统一系统主动恢复；迁移 `321_group_quality_active_recovery.sql` 升级已有分组目标，保留各指标的自定义阈值及禁用状态。鹈鹕、糖果、生成耗时与模型一致性检测继续通过“智力检测”入口配置，独立持有限制。

按 **分组 + 账号 + 公开模型**统计滚动最近 **1 小时全部真实文本请求**，不再只取最近 100 次。数据库直接聚合，不把全量请求加载进服务进程。策略生效前、其他分组/模型、主动测试及非文本生成不混入该目标；缺少对应指标上报的请求记为未知，不能当作零缓存或零延迟。

每个启用指标默认至少 **20 个有效样本**；约每 **15 秒**检查，至少 **2 批**异常确认，每批至少 **5 个该指标的新样本**。可用率异常持续 **60 秒**，缓存率、首字和 TPS 异常持续 **300 秒**才暂停。各指标分别累计证据和计时；持续时间本身不代替新样本。额外的快速故障保护会在最近 60 秒出现连续 3 次已确认上游失败时暂停，不让大量旧成功稀释突发故障。

| 指标 | 新策略异常目标 | 恢复目标 | 统计口径 |
| --- | --- | --- | --- |
| 缓存率 | < 80% | ≥ 85% | 有效缓存读取 token 总和 / 对应有效输入 token 总和 |
| 可用率 | < 90% | ≥ 95% | 已确认成功尝试 / 已确认真实尝试 |
| 输出 TPS | < 30 token/s | ≥ 36 token/s | 有效输出 token 总和 / 首字后生成秒数总和 |
| 首字 P90 | > 15 秒 | ≤ 12 秒 | 有效流式请求首字耗时的第 90 百分位 |

等于目标值算达标。四项持续异常均可硬暂停该账号的当前模型；单纯低缓存率也不再仅减少新分配。首字目标是统计保护条件，不是客户请求的提前中止超时。采集不完整或样本不足不等于质量失败。

### 系统主动复测

暂停后停止该账号/模型的客户调度。首次冷却 5 分钟，真实复测失败按约 5 / 10 / 20 / 40 / 60 分钟退避并带少量错峰，最高 60 分钟。冷却结束由系统请求原账号、原公开模型，不放客户请求试运行。请求沿用所属分组的渠道映射，再应用账号模型映射；保护状态与统计仍归属原公开模型，避免别名被当作真实上游模型误测。

- 至少两批独立检测，每批至少 5 个有效恢复样本，两批新证据间隔至少 120 秒；每批及整体都必须达到全部已启用指标的恢复门槛。
- 缓存检测使用每批专用稳定会话与固定长前缀，先预热，再重复请求。预热消耗及失败计入预算和可用性证据，但不纳入缓存复用率分母。
- 测量实际流式首字、完成耗时和供应商上报用量。主动 TPS 至少输出 128 token 才有有效样本；缺报、输出过短、协议不兼容均不能伪造达标。
- 默认单协议且启用缓存时每轮 12 次实际请求；自适应双协议／三协议分别约 16／18 次，每个原生协议都参与预热和重复验证。达到各指标的有效尝试数后结束该批，兼容重试也逐次计数，单轮最多 20 次实际尝试、10 分钟。跨实例最多 4 个被动恢复探测，同账号同模型不重复并行探测。
- 探测使用现有主动检测的全局/账号预算，单独标记恢复用途，不进入真实流量成功率、缓存率、首字和 TPS 统计。预算不足、任务中断或缺少有效证据保留暂停并等待后续复测，不冒充上游异常加重退避。
- 恢复只解除本策略的限制；人工停用、智力检测失败和其他独立限制仍有效。已配置明确模型且从无真实业务历史的目标可先进行系统验证；没有已知模型时不猜测模型。

现有 Bedrock／TypeSafe 测试适配器无法测量缓存、流式首字或 TPS；启用这些指标时预检即显示不支持并延后，不消耗上游请求，也不解除暂停。仅启用可用率时仍可检测。

主动恢复成功后保留完整一小时真实历史，并单独累计恢复后的新请求。再次暂停须同时满足历史窗口和恢复后有效异常证据，不能仅凭恢复前的失败立即重封。持续 10 分钟新健康证据后重置异常退避。主动验证通过与真实流量达标分别展示，不能用测试结果美化真实业务指标。

### 调度与报告

分组质量保护关闭客户恢复试运行、验证流量配额和受保护账号的应急兜底。即使全组没有正常供给，也不放行该保护暂停的账号模型；已有配置允许的健康备用分组仍按正常路径处理，否则返回不可用。调度选路和数据库最终准入均检查当前策略，旧兜底租约及续期路径已移除，旧快照或旧请求标记不能越过分组质量暂停。

未暂停的样本不足账号继续正常采样，并遵守账号原有并发和全部硬准入。已验证健康与样本不足账号沿用同一候选排序规则；同一用户/会话继续保持现有账号亲和。确认故障后迁移，原账号恢复不会自动抢回用户归属。详见[用户亲和与迁移](passive-quality.md#用户亲和与迁移)。

最近一小时报告由后台约每分钟生成快照，显示窗口起止及生成时间。首个快照未生成或超过两分钟未更新时显示等待/过期。贡献明细最多展示 200 行并提示截断，整体统计不受明细分页影响；历史验证和兜底用途仍保留作审计。主动恢复证据单列请求数、批次、时间、结果和四项指标。

迁移 323 将剩余分组目标统一为主动恢复，并归档旧配置、作废旧探测代次及客户试运行/应急兜底租约。管理 API 拒绝 recovery_mode=traffic，不再提供可用性优先或客户验证配额开关。旧验证预算与兜底汇总接口字段一并删除；归档及贡献明细中的历史用途仅用于审计。多实例需协调升级，不能在混合旧实例状态下承诺新语义已全面生效。

## 鹈鹕检测总耗时

在“主动检测”中编辑策略，进入“质量自动化”，在鹈鹕（HTML/SVG）项目中启用“限制检测总耗时”，按秒填写上限。例如设置 60 秒，60 秒通过、超过 60 秒不通过。该条件可与人工评审同时使用；在“全部自动检测通过”模式中，即使项目选择人工评审，耗时条件也必须通过。

- 总耗时累计本次完整生成、协议兼容重发、自动重试及重试等待，不计本地账号/工作线程排队。手动重试重新计时；历史结果不回填之前未记录的重试时间。
- 耗时条件在执行结束后判定，保留生成的 HTML/SVG。启用后要求检测成功完成，快速报错不算耗时达标。它不是提前中止请求的硬超时；原有请求执行超时仍有效。
- 超过上限执行策略配置的不通过动作（例如暂停调度）；“全部通过”模式会停止该账号当前模型本轮后续检测。人工点“通过”不能抵消耗时超限，下一轮耗时和其他自动条件达标后按通过动作恢复，其他策略的限制仍然有效。
- 管理端检测历史和渠道监控鹈鹕预览显示总耗时；历史中的耗时超限结果显示为“质量不通过”，可按失败筛选。

## 鹈鹕自动视觉评审

鹈鹕（HTML/SVG）规则可开启自动视觉评审；新增开关默认关闭。全局裁判账号、裁判模型和独立每日调用上限在“检测运营”配置。应选一个与被测账号及其父账号、凭据均独立的 OpenAI OAuth/API Key 账号；被测账号不能给自己评审。现阶段不支持其他供应商账号作裁判。视觉裁判每次调用仍计入现有主动检测请求与 Token 预算。

评审在生成完成后运行，不计入鹈鹕配置的生成总耗时。独立无网络 Chromium sidecar 在隔离容器中运行 HTML/SVG，截取第 0、0.7、1.7、2.9 秒四帧；主服务不执行生成脚本。请按 `renderer/README.md` 安装 `review-renderer` sidecar，并应用数据库迁移后再启用规则。未安装 sidecar、渲染失败、裁判账号/额度不可用或置信度不足均显示“待复核”，不降低被测账号的通过率。

固定标准检查鹈鹕特征、自行车结构、骑乘关系、轮子/脚踏动态和画面完整性；通过需要五项全部满足。首轮通过即可通过。首轮失败会对同一作品独立再判一次，只有两次都失败且至少一项失败标准相同才记失败；其他情况转待复核。评审日志保存在管理员检测结果中，普通用户结果不暴露裁判身份或内部评语。管理员复核可改判具体一轮，系统同步更正该轮最近通过率证据；普通执行重试不能覆盖已确认失败。总耗时门槛仍独立生效，人工通过不能豁免超时。

检测结果页默认勾选“全部结果”，自动评审或人工审批后仍保留鹈鹕动画，并展示当前判定和管理员改判入口。取消勾选后，仅显示尚待人工复核的自动评审结果；其他检测正常显示。每日额度按 UTC 自然日独立统计，预占的评审调用不因超时或网络错误退还。

鹈鹕卡片的大预览始终展示最新一轮结果，右侧最多展示前两次成功生成的动画缩略图，并标注生成时间；点击小图可单独放大查看。手机窄屏下，小图排列在大图下方。历史不足时只显示已有作品，完整记录仍通过“查看历史”打开。近期作品与当前结果使用相同的分组权限、账号、检测类型、模型和推理强度范围；最新一轮失败时，不使用旧作品替代最新结果。

## 随机能力题库

在检测类型中选择“随机能力检测”，再纳入主动策略。原有鹈鹕、糖果、统计、模型一致性和人工评审方式继续可用。

- 每轮最多 1–5 道题，可配置通过题数；达到通过门槛或已不可能通过时提前结束。
- 内置随机逆向算术、状态追踪、指令遵循题族，也支持最多 50 道自定义题。配置存于已有定义的 Prompt 字段，由结构化编辑器维护。
- 每轮生成独立随机种子，保存实际题目、标准答案、返回文本、逐题结论、总判定。整数比较和精确文本比较由程序执行，不让被测模型自评。
- 一轮结果复用现有策略动作、组合条件、检测顺序和自动恢复流程。仅 HTTP 成功但答题失败不会算通过，也不会使该账号同一模型的后续检测继续执行。
- 传输失败、认证错误、截断等显示“执行失败，能力未知”。是否暂停由主动策略的执行失败规则决定；不把它直接归因为降智。
- 每题复用已有最多一次瞬时故障重试。请求尝试与 token 用量跨题累计；缺失用量保持未知。

题目应先在可信上游校准。随机题能降低固定答案记忆的干扰，但不是模型身份认证，也不能保证检测出所有能力下降。能力检测结论仍由账号自己的保护规则处理，不根据供应商关系传播到其他账号。

## 检测预算与动态频率

在“预算与供应商”中配置。迁移 `294_quality_operations.sql` 新增独立账本、供应商成员和健康频率状态。预算与健康降频默认关闭，不改变现有策略的生效开关。

- 同时支持全局和每账号的每日请求、Token 上限，0 表示该项不限额。UTC 00:00（北京时间 08:00）重置；页面展示本地时区的重置时间。
- 可将全局与每账号每日请求、Token 上限的 0–50% 留给恢复探测，默认 0 不预留。普通检测不能占用尚未消耗的恢复预留；恢复探测仍计入同一日总额，必须同时通过全局和账号准入，不会增加总额度。恢复使用量单独展示；分组质量目标的系统主动复测也计入此账本。
- 质量管理中的手动计划运行、自动检测、每次重试、协议兼容尝试、每道能力题、统计恢复探测和被动恢复探测都走同一请求准入。Antigravity 的检测专用发送路径也已接入。客户推理流量、账号页独立调试、模型列表和 OAuth 刷新不属于此预算。
- 发送前在 PostgreSQL 事务内同时预占全局和账号额度，多实例共享。请求预算是硬准入限制；Token 使用请求大小、输出限额和最低预占估算，不是供应商账单金额的硬上限。实际用量高于预占时仍如实结算，并阻止后续超预算请求。
- 完整用量到达后结算；缺报、未完成的流或进程中断保留预占，显示为未知/待结算，不能当作零消耗。OpenAI 的缓存 Token 已含在输入中，Anthropic 的独立缓存输入需计入，推理 Token 不重复叠加。结算幂等且归属原始预占日期，跨日完成不会挪用新一天的预算。
- 账本独立于检测结果，删结果不返还预算。请求明细保留 30 天、日汇总保留 90 天，质量后台每小时分批清理；未知用量仍保留在所属日期汇总里。页面目前展示当天汇总。
- 达到预算或无法读取预算时，本次检测标记跳过，保留已有保护状态；不计作上游失败、不增加异常退避、不自动解除暂停。被动探测等待预算重置或短暂重试后再探测。
- 连续完整健康达到配置轮数后，付费复测间隔从起始值逐次翻倍至上限。低成本统计继续按计划执行；出现新的被动异常、当前统计不满足规则或真正检测失败时不再沿用健康降频。原有异常退避、Retry-After 与计划运行时段仍有效。
- 手动完整运行绕过动态频率和供应商复测间隔，但遵守预算。计划/题库变化、预算频率配置版本变化会使旧健康等待失效；旧轮次完成不能覆盖新轮次。自动恢复仍要求各自原有的验证证据。

## 供应商故障聚合

供应商是管理员显式维护的上游账号集合，不复用定价渠道或客户业务分组。每个账号只归属一个供应商，不读取或展示凭证 URL。配置和删除不会直接改变账号调度开关。

聚合基于各成员最近一次**实际质量检测请求**的结果，默认最近 600 秒、至少 2 个账号发生网络/服务端失败、占有新鲜证据账号的 60% 才显示共同故障。认证、余额/配额、限流、请求兼容性和取消分别显示，不扩散成整个供应商故障。真实流量仍由被动策略负责；本版本不将缺少错误类型的被动失败直接归因给供应商，也不将能力题的错误答案当作供应商基础设施故障。

共同故障期间，同一供应商的自动检测共用复测间隔，跨实例锁防止同时大量发起新检测轮次；获准轮次可以继续串行题目与重试，预算仍逐次检查。这是请求启动间隔，不承诺上游长请求只有一个在途。手动检测可立即验证，成功仅更新该账号证据。各账号原有的暂停独立验证恢复，不会因为一个账号恢复就批量放开同组账号。

证据过期后显示“证据不足”，不是“已恢复”。更改供应商成员或阈值会重新积累证据；变更前在途请求的旧结果不能成为新配置的证据。聚合不新建供应商级调度暂停，不修改现有按账号的主动保护粒度。

## 验证和升级

本地验证另覆盖并发预算准入、跨日和幂等结算、未知/流式用量、暂缓不误触发保护、供应商隔离及配置栅栏、动态频率和旧规则移除。原有本地验证覆盖随机题参考答案、题库校验、提前结束、传输未知、用量累加、质量优先级副本、并发上限、代理池跨实例额度、连续恢复、独立限制、总览筛选分页、页面导航、题库编辑、历史结果展示和中英文资源。

历史迁移 `317_unified_channel_quality.sql` 将“全部自动检测通过”模式的通过率条件收敛为最新一轮，并合并已有分组目标与旧自定义策略的重复分组覆盖；其中对旧默认评分权重的更新保留原迁移记录，评分配置随后由迁移 `322` 归档移除。现有目标阈值、题库及历史结果保持原样。迁移不会仅因配置变化解除主动暂停。

变更前配置保存在 `quality_management_config_archive`，便于核对；回退应用二进制不会自动还原配置及已合并的状态，发布前应保留正常数据库备份。迁移 `318_retire_custom_passive_rules.sql` 进一步彻底移除全部旧规则：归档后删除规则及其状态、试运行租约，仅解除旧规则自身的账号限制，并产生 `custom_rule_retired` 事件。分组目标、手动停用和智力检查暂停保留。管理接口与数据库约束共同阻止重建旧规则；旧编辑器及历史回放接口已移除。多实例需协调升级，回退二进制不能恢复已删除状态。代码完成不代表生产安装或策略已经启用。

迁移 `322_retire_channel_quality_score.sql` 将最终评分配置（含版本及采集起点）归档到 `quality_management_config_archive` 的 `retired_score` 记录，再移除专用配置表。共享流量证据、保护与恢复状态、检测结果及原有归档保留；历史迁移不改写。回退旧二进制前需恢复其评分配置表，不能只替换应用文件。

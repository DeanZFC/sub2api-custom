# 严格主备账号调度

## 配置

管理后台 → 分组管理 → 编辑分组 → **严格主备**。

1. 先将账号绑定到分组。
2. 开启严格主备，在“第 1 优先级”选择主账号；在“第 2 优先级”选择备用账号。
3. 可以继续添加、上移或下移层级，保存后生效。最多手动配置 10 层、1000 个账号，账号不能重复，每个手动层级至少一个账号。
4. 本分组所有未配置层级的账号自动组成最后一级，排在全部手动层级之后；无需逐个添加，移出手动层级的账号也会回到最后一级。

新分组默认关闭。创建分组后再绑定账号、编辑层级；复制分组会将严格主备重置为关闭，避免沿用原分组的账号引用。关闭开关会保留已填写的有效层级。

配置存储为 groups.strict_failover，例如：

    {"enabled":true,"tiers":[[11,12],[21,22]]}

同一次模型请求先使用账号 11、12，只有它们都明确不能承接本次请求或不满足利润条件时，才继续使用 21、22；若第二级同样没有符合条件的账号，再尝试本分组未配置层级的其他账号。已知的模型不支持、限流等状态可在选号时确认；需要实际请求确认的上游故障，在允许的同账号重试结束后记录证据，再在同一次请求内继续选择同层或下一层。最后一级只包含当前分组的账号，不会自动加入其他分组的账号。普通账号优先级、评分、成本、订阅偏好和会话粘性仅在选定层级内生效。

所有层级（包括自动最后一级）统一使用分组现有利润控制，不单独设置利润阈值。利润控制开启时，每个候选账号都需满足本次请求对应的利润条件；本级仍有符合条件的账号就留在本级，全部不符合时继续下一级。保留现有利润计算方式、用户价格覆盖和适用请求范围；关闭利润控制时不按利润筛选。

## 可用性规则

每次选号读取配置中的账号及当前分组成员关系，包括调度缓存通常会过滤掉的禁用、冷却账号，并将当前分组中未配置层级的账号补在最后一级。按层级顺序选取第一个还有符合可用性及利润条件账号的层级。

可作为不可用依据：

- 账号删除、移出分组、停用、关闭调度、到期自动暂停。
- 已生效的账号或模型限流、冷却、额度耗尽、主动测试保护。
- 当前平台、模型、端点或 WebSocket 传输能力不支持，隐私要求不满足；影子账号的母凭据不可用。
- 在现有利润控制适用范围内，账号不满足当前请求的利润条件。
- 本次请求完成允许的同账号重试后，收到已由转发服务判定允许换号的实际上游 4xx/5xx（包括 401、429、5xx 等），或已分类的凭据、余额、流式限流/过载错误。可安全重放的请求级或服务商级上游失败，也可作为该账号本次请求无法服务的依据，不改变原有的全局账号健康归因。
- 已分类的账号转发/传输失败，或实际发起请求后尚无语义输出便超时、异常截断，在允许的同账号重试耗尽后可作为本次请求的不可用依据；仍遵循原有安全重放限制。

以下情况不会凭自身触发降级：本地并发满、排队、评分低、探测预算耗尽、数据库读取失败、没有故障证据的候选排除、没有明确账号转发失败分类的本地合成 502/504。客户端取消或请求总期限耗尽时直接终止；已经输出语义内容或无法确认安全重放时，不重放到其他账号。若当前层仍有其他符合条件的账号，先尝试同层；若只剩未知状态则返回错误，不能跳层。已有持久化冷却/保护状态仍遵循系统原有健康规则。

严格模式按层级遍历分组内有限的候选账号，同一个账号在允许的原地重试结束后进入本次请求排除集，不会因 503 退避而重新放回。普通模式的全局换号次数、利润终检否决次数、Responses 首次输出超时换号次数及 OAuth 429 换号次数上限不会截断严格层级遍历；同账号重试规则、请求取消和超时、安全重放及凭据归属限制继续有效。候选全部排尽或只剩状态不明的账号时终止。没有已记录不可用状态的上游问题需要实际请求提供证据；本功能不主动发送收费探测请求。

## 恢复、续接与兜底

- 账号状态恢复或利润条件重新满足后，下一次重新选号会重新从第一层开始。已经发出的请求按原账号完成，排队请求沿用当次选号结果。
- 普通新请求不会因会话粘性长期滞留备用层。
- 不可迁移的 previous_response_id 必须保持原账号，即使同层另一个账号可用也不能替换凭据。原账号不在当前可用层时返回 strict_failover_owner_bound（HTTP 409），客户端需携带完整上下文新开请求。
- WebSocket 后续 turn 会复核当前层与连接账号；层级变化时要求带完整上下文重连，不在原连接内混用凭据。
- 所有手动层级和自动最后一级都明确不可用或不满足利润条件后，才允许 API Key 已配置的跨分组兜底；未知状态、预算、并发或一般选取失败不能触发它。备用分组自身仍执行其严格主备及利润控制规则。
- 启用严格主备时，Claude Code 客户端限制、prompt-too-long 的历史跨组兜底不会绕过层级限制。
- 固定账号获取模型列表、管理员主动测试、已创建媒体任务的查询/下载不是新推理调度，不改写其原有账号归属。

## 诊断与升级

日志 strict_failover_tier_selected 记录 group_id、model、tier 和前层逐账号不符合条件的原因；strict_failover_all_tiers_unavailable 表示所有手动层级及自动最后一级均已确认不符合条件。strict_failover_unconfirmed 表示证据不足，请求没有启用备用路由。

迁移 325_group_strict_failover.sql 添加 JSONB 列，默认关闭；认证缓存快照版本升级至 29，同时保留按张计费配置；严格主备配置进入认证投影且切片独立复制。账号层级 ID 仅在管理员 DTO 暴露，不在普通用户分组 DTO 暴露。部署时须使用包含该迁移的新服务端与对应前端；本地实现和测试不代表已发布或已安装到生产环境。

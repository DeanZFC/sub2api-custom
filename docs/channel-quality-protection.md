# 渠道质量自动化

入口：**渠道质量管理 → 新建/编辑检测规则 → 质量自动化**，默认关闭。
选择“指定账号”或“分组内所有账号”，再为已选择的检测类型分别配置判断条件及动作。
分组汇总检测不调整账号，以免用整个分组的指标误判某个账号。

**用户投票目前暂停开放**：用户端不显示质量评议和投票按钮，也不请求投票列表；旧客户端读取列表得到空数组，提交投票返回 403。下文投票机制保留为规则说明，普通用户当前无法提交新票。此调整不清空历史票数，也不修改已有检测规则。

管理员登录后，可在「渠道质量检测」的当前账号检测结果下直接「判定通过」或「判定不通过」。入口仅用于已启用投票评议的保护规则；一票判定不受用户票数门槛限制，立即执行该规则配置的满足/不满足动作。通过仍受自动检查和其他规则约束；不通过判定会保留到该检测的新一轮或管理员改判。质量保护暂停的账号仍向管理员展示，手动关闭调度的账号不参与。服务记录判定人和时间，并拒绝对过期轮次的操作。普通用户不请求或接收管理员评议信息。

## 每种检测独立配置动作

每个检测类型都有“满足条件 / 通过时”和“不满足条件 / 不通过时”两个动作区。
每个动作区可独立组合：

- 调度：保持当前调度、检测自动暂停、解除本规则的自动暂停。
- 分组：保持当前分组，或调整到多个指定分组。支持按名称、ID 搜索；目标须与检测分组属于同一平台，每侧最多 100 个。

仅想做升降级时，两侧调度都选“保持当前调度”。需要不通过后彻底暂停时，才选择“检测自动暂停”。
旧规则没有动作配置时，保持原有行为：不通过自动暂停，通过解除本规则暂停，分组不变。

分组调整只管理该检测规则两种结果所选分组的并集，其他分组保持不变。例如通过分组为“优选、快速”，不通过为“基础”：
通过时移除“基础”并加入“优选、快速”；不通过时执行相反调整，未配置的“内部专用”等分组不受影响。
一侧可不选分组，表示从本规则管理范围全部移除；至少另一侧须选择一个分组。
账号被移出原检测分组后仍会继续复测，不会因为降级后离开原分组而无法升级。启用分组动作时，一小时统计按该账号和模型跨分组采集，迁移后产生的新流量仍参与判断。分组汇总检测仍只统计指定分组。

多个检测条件共用目标分组时，相关条件全部通过才升级；任一条件不通过优先降级，不能由另一条通过结果覆盖。
缺少有效样本、投票未达到门槛或新一轮尚未完成时，保留上次分组与调度，不当作通过。整轮开始时会重置各类型本轮判定和投票资格，只有本轮相关类型全部通过才能升级；本轮已经明确失败可立即降级。单条手动重试只重置该类型。

## 判断条件

- 一小时统计：成功率、缓存率填百分比（如 `80` 表示 80%），平均首字延迟用毫秒。
- 普通测试：可按检测耗时设置阈值；数字测试还可按输出数字设置阈值。
- 阈值是**异常阈值**，支持严格“小于”和“大于”：任一条件命中即不通过；等于阈值不触发异常。都未命中且其他条件通过时才执行通过动作。
- 可配置最低样本数。没有数据或有效样本不足时保持待评估，不按零计算，也不解除已有暂停或升级分组。
- 配置了“不通过”动作，或开启“最终执行失败时判定为不通过”时，定时测试最终失败会立即判定不通过并执行该动作。定时测试先按现有策略额外重试三次；两者都未配置时，执行失败保持待评估。
- 答案支持完整匹配、包含匹配、数值匹配。图形是否画对不能可靠地用 HTML 字符串判断，鹈鹕等图形检测建议使用投票。

## 缓存率和糖果检测示例

同一账号选择“近一小时统计”和“糖果”两个检测类型，分别启用自动化。

1. 统计检测：异常阈值为“缓存率小于 80”，最低样本设为 10。
2. 糖果检测：预期答案填 `29`，选择“数值相等”。
3. 两种检测都配置：通过分组“优选、快速”，不通过分组“基础”；两侧调度都保持不变。

有足够样本且缓存率达标、糖果答案正确时，账号进入“优选、快速”；任一检测不通过时进入“基础”。
新增条件尚未有有效结果时不会因为另一项通过就提前升级。

## 返回模型一致性

在**渠道质量管理 → 新建/编辑检测规则 → 检测类型**中选中“返回模型一致性”，并选择要检测的模型。
该类型使用固定简短请求，无需填写提示词。结果直接显示请求模型、上游请求模型、实际返回模型以及“一致 / 不一致 / 无法确认”。
比较对象是应用账号模型映射后实际发给上游的模型名，与上游响应中的 `model` 字段；用户请求的别名仅用于展示，正常模型映射不会因此误判。
若一次响应报告了多个模型名，所有返回模型都必须符合匹配规则。

在该类型的**质量自动化 → 模型匹配方式**中可以配置：

- **严格匹配**（默认）：返回模型必须与实际发送的上游模型完全相同。
- **允许日期快照版本**：允许完全相同，或仅在实际发送模型后追加 `-YYYY-MM-DD` 日期后缀。例如请求 `example-model`，返回 `example-model-2026-09-21` 可以通过；任意前缀、其他模型名或其他后缀不会通过。

模型一致性本身就是判定条件，无需配置预期答案，也不支持投票；可以额外配置检测耗时阈值，以及通过、不通过时的调度和多分组动作。
未启用质量自动化时不执行该类型配置的分组和调度动作。匹配方式默认严格匹配，已保存的匹配方式仍用于手动检测。旧规则若开启了“成功后自动恢复”，该类型只有明确一致时才允许恢复。

未返回模型字段、未取得实际发送模型或证据无效时为“无法确认”，不因缺少模型证据执行升级、降级、暂停或恢复动作。如果额外配置了检测耗时阈值，已观测到的耗时异常仍可判定不通过。
传输失败在现有重试全部失败后处理：配置了“不通过”动作或开启“最终执行失败时判定为不通过”时触发不通过动作，两者都未配置时保持待评估。
正常完成请求但模型不一致的记录会展示“不一致”，不会把请求完成误写为模型验证通过。

此检测只核对上游自报的模型元数据，不能证明其实际使用的模型权重、身份或能力；上游可自行改写返回的模型字段。

## 鹈鹕检测和用户投票

为鹈鹕等图形检测开启“由用户投票判断结果”，配置“通过票数达到”和“不通过票数大于”的门槛。
例如通过门槛 `3`、不通过门槛 `2`：至少三张通过票可判定通过；第三张不通过票判定不通过。
再分别为通过、不通过配置升级分组、降级分组或调度动作。

开启投票时，预期答案仅作为参考答案展示给用户，不再作程序字符串匹配。
每个用户每轮一票，允许改投；不通过票门槛优先，且通过票不能覆盖自动指标异常。
票数不足不触发新动作。每次重新执行开启新一轮，旧票不累加，旧结果不能继续投票。
失败或无有效输出的结果不开启投票。

用户在渠道质量检测页的“质量评议”区查看本轮输出并投票。
检测结果按账号当前分组显示；原分组仍绑定时优先使用原分组，否则使用 ID 最小的有效当前分组。无当前分组的账号结果不向用户展示，分组聚合统计仍保留原分组。

只有有权查看实际展示分组的已登录用户可以投票。接口只公开账号 ID，不公开账号名称或自动化配置。账号移组后重新校验权限；如果有效投票本身导致投票人失去访问权限，仍提交该票及其动作，仅返回移组前已授权的信息。

## 自动暂停与手动停用

选择“检测自动暂停”后，账号状态显示 **检测自动暂停**，并记录原因。
普通请求不再调度该账号，管理员的“调度”开关保留原值。
选择“解除本规则的自动暂停”只清除该规则的暂停，所有规则的暂停原因均解除后才恢复。
选择“保持当前调度”不会清除既有暂停。

定时账号检测仅选择未删除、手动调度开关开启、状态为“正常”或“检测自动暂停”的账号。
在账号排队等待期间关闭调度，会在调用上游前再次检查。
手动关闭调度的账号不参与复测，不会被自动打开或自动调整分组；其他错误状态也不会被自动化覆盖。

正常结果列表隐藏自动暂停账号；独立投票区保留其新成功结果，供用户重新评议。
后台 OAuth 凭据续期继续运行，避免因检测暂停失去复测能力。

禁用、删除检测规则或修改保护条件时，会清理对应旧判定与投票资格。
如果没有其他暂停原因且手动调度仍开启，可解除该规则造成的暂停；仅修改名称或执行时间不会重置判定。

调整同一检测目标的条件、模型或检测类型时，会保留已经自动移组的账号登记，以便继续复测。仅停用规则也保留登记，但不执行检测或接受投票，重新启用后可继续跟踪。关闭分组自动化、改变检测目标或删除规则后解除登记，已调整的分组不会被静默改回。

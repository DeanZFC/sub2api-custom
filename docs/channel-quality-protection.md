# 渠道质量自动化

入口：**渠道质量管理 → 新建/编辑检测策略 → 质量自动化**，默认关闭。
一条策略选择 1–100 个同平台、已启用的普通分组，以及 1–32 个已启用检测项目。系统检测所选分组内符合条件的账号，按账号 ID 去重；每个项目分别配置答案、异常阈值、人工评议、优先级和通过/不通过动作。

完整执行流程、通用配置示例、冲突检查及旧配置迁移见 [渠道账号检测策略](channel-test-strategies.md)。糖果、鹈鹕仅是可选检测项目，不再有专用运行模式；新增策略使用 `group_ids` 和 `test_definition_ids` 数组，不再选择指定账号或分组汇总模式。

**用户投票按检测项目单独开放，默认关闭**：在检测计划内，对希望开放的检测项目启用“人工评议”，再打开“允许用户投票”。只开启人工评议时仅管理员可以判定；用户端只显示明确开放且当前有权限的投票项目，关闭的项目在接口上也拒绝提交。

管理员登录后，可在「渠道质量检测」的当前账号检测结果下直接「判定通过」或「判定不通过」。入口仅用于已启用人工评议的保护规则；管理员判定不受用户票数门槛限制，并立即重新计算本轮动作。分组处理时，管理员判定优先于普通自动结果和用户投票，但不能绕过“晋级前必须通过”的自动条件，也不会解除其他检测规则的暂停。判定保留到该检测的新一轮或管理员改判。质量保护暂停的账号仍向管理员展示，手动关闭调度的账号不参与。服务记录判定人和时间，并拒绝对过期轮次的操作。普通用户不请求或接收管理员评议信息。

## 每种检测独立配置动作

每个检测项目都有“满足条件 / 通过时”和“不满足条件 / 不通过时”两个动作区，可独立组合：

- 调度：保持当前调度、检测自动暂停、解除本规则的自动暂停。
- 分组：保持当前分组，或调整到指定分组。每侧须选择策略范围内的 1–100 个分组，支持按名称、ID 搜索。

仅想做升降级时，两侧调度都选“保持当前调度”。新启用的保护规则默认通过时解除本规则暂停、不通过时自动暂停，应按实际需要调整。缺失动作表示保持当前状态，不会隐式暂停或恢复；升级迁移会把旧配置的隐含动作转换为明确动作。

“调整到指定分组”会替换账号的全部原分组，只保留目标分组。例如通过目标为“优选、快速”，不通过目标为“基础”：通过后账号只属于“优选、快速”，不通过后只属于“基础”，原有“内部专用”等其他分组也会移除。指定分组动作不允许空目标；希望不改组时选择“保持当前分组”。目标必须在本策略范围内，因此自动切组后下一轮仍可检测。

每轮开始时固定“账号 × 检测项目”名单。同一账号本轮中途切组不会重复入队或跳过剩余项目；新加入账号下一轮才检测。账号被人工移出全部策略分组后，下一轮不再纳入，系统不依赖旧的移组账号登记继续复测。账号统计按账号与所选模型跨分组采集，迁移前后符合时间窗口的流量均可参与判断。

## 优先级与必须通过的条件

分组处理按以下顺序选择本轮动作，调度暂停/恢复仍按各项检测自己的保护状态处理：

1. **必须通过的自动条件**：仅自动条件可启用。尚未完成或未通过会阻止所有通过分组动作，包括管理员判定通过；明确失败优先执行该条件的不通过分组动作。未配置切组动作时，仍允许其他明确失败执行降级。
2. **管理员本轮判定**：优先于普通自动结果和用户投票。本轮后续普通结果不能推翻管理员判定，下一轮清空。
3. **普通规则优先级**：数值越大越优先，范围为 0–1000。同优先级自动条件全部通过才执行通过动作；任一失败优先执行失败动作。未判定的人工评议项目不阻止其他规则；已有用户投票结论按项目优先级参与处理。

同层、同一判定的多个指定分组动作合并目标后一次替换。若最终只需要一个分组，让这些动作选择相同的单个目标。高层已有明确的“保持当前分组”决定时，也会阻止低层动作改组。

缺少有效样本或新一轮尚未完成的自动条件保持待判定，不按通过处理；不代表所有其他优先级的规则都停止处理。开启新一轮时清空上轮判定与票数，在出现有效新结论前保持当前分组；单条手动重试只重置该项目。

## 判断条件

- 一小时统计：成功率、缓存率填百分比（如 `80` 表示 80%），平均首字延迟用毫秒。缓存率仅使用流式和 WebSocket 请求的有效缓存样本，按输入 Token 加权；同步请求不计入缓存率和缓存样本数。
- 普通测试：可按检测耗时设置阈值；数字测试还可按输出数字设置阈值。
- 阈值是**异常阈值**，支持严格“小于”和“大于”：任一条件命中即不通过；等于阈值不触发异常。都未命中且其他条件通过时才执行通过动作。
- 可配置最低样本数，各指标分别判断自己的有效样本数。没有数据或有效样本不足时，该条件保持待评估，不按零计算，也不依据该条件解除暂停或升级分组。
- 配置了“不通过”动作，或开启“最终执行失败时判定为不通过”时，定时测试最终失败会判定不通过；存在明确动作时执行该动作，缺失动作时保持状态。定时测试先按现有策略额外重试三次；两者都未配置时，执行失败保持待评估。
- 答案支持完整匹配、包含匹配、数值匹配。图形是否画对不能可靠地用 HTML 字符串判断，鹈鹕等图形检测建议使用投票。

## 缓存率和数字检测示例

策略分组选中“优选、快速、基础”，选择“近一小时统计”和一个数字检测项目，分别启用自动化，并将两项优先级都设为 `0`。

1. 统计检测：异常阈值为“缓存率小于 80”，最低样本设为 10。
2. 数字检测：按实际题目配置预期答案，例如 `29`，选择“数值相等”。
3. 两种检测都配置：通过分组“优选、快速”，不通过分组“基础”；两侧调度都保持不变。

有足够样本且缓存率达标、数字答案正确时，账号只保留“优选、快速”分组；任一检测不通过时只保留“基础”。同优先级新增自动条件尚未有有效结果时，不会因为另一项通过就提前升级。若该条件也必须阻止更高优先级或管理员的通过动作，应勾选“晋级前必须通过此自动条件”。

## 返回模型一致性

在**渠道质量管理 → 新建/编辑检测策略 → 检测类型**中选中“返回模型一致性”，并选择要检测的模型。
该类型使用固定简短请求，无需填写提示词。结果直接显示请求模型、上游请求模型、实际返回模型以及“一致 / 不一致 / 无法确认”。
比较对象是应用账号模型映射后实际发给上游的模型名，与上游响应中的 `model` 字段；用户请求的别名仅用于展示，正常模型映射不会因此误判。
若一次响应报告了多个模型名，所有返回模型都必须符合匹配规则。

在该类型的**质量自动化 → 模型匹配方式**中可以配置：

- **严格匹配**（默认）：返回模型必须与实际发送的上游模型完全相同。
- **允许日期快照版本**：允许完全相同，或仅在实际发送模型后追加 `-YYYY-MM-DD` 日期后缀。例如请求 `example-model`，返回 `example-model-2026-09-21` 可以通过；任意前缀、其他模型名或其他后缀不会通过。

模型一致性本身就是判定条件，无需配置预期答案，也不支持投票；可以额外配置检测耗时阈值，以及通过、不通过时的调度和多分组动作。
未启用质量自动化时不执行该类型配置的分组和调度动作。匹配方式默认严格匹配，已保存的匹配方式仍用于手动检测。该条件只有明确通过时才会执行已配置的恢复动作。

未返回模型字段、未取得实际发送模型或证据无效时为“无法确认”，不因缺少模型证据执行升级、降级、暂停或恢复动作。如果额外配置了检测耗时阈值，已观测到的耗时异常仍可判定不通过。
传输失败在现有重试全部失败后处理：配置了“不通过”动作或开启“最终执行失败时判定为不通过”时判定不通过，并执行明确配置的动作；两者都未配置时保持待评估。
正常完成请求但模型不一致的记录会展示“不一致”，不会把请求完成误写为模型验证通过。

此检测只核对上游自报的模型元数据，不能证明其实际使用的模型权重、身份或能力；上游可自行改写返回的模型字段。

## 图形检测和用户投票

为指定计划中的鹈鹕等图形检测开启“启用人工评议”及“允许用户投票”，配置“通过票数达到”和“不通过票数大于”的门槛。同一检测类型在另一条计划中的开关互不影响。
例如通过门槛 `3`、不通过门槛 `2`：至少三张通过票可判定通过；第三张不通过票判定不通过。
再分别为通过、不通过配置升级分组、降级分组或调度动作。

单独打开或关闭“允许用户投票”保存后立即生效，无需等待下一轮。关闭会隐藏入口并拒绝新投票，保留已有票数、管理员判定与当前调度/分组；重新打开可继续当前轮。修改票数门槛等判断条件仍会重置对应旧轮次，需要重新执行检测。

开启投票时，预期答案仅作为参考答案展示给用户，不再作程序字符串匹配。
每个用户每轮一票，允许改投；不通过票门槛优先，且通过票不能覆盖自动指标异常。
票数不足不触发新动作。每次重新执行开启新一轮，旧票不累加，旧结果不能继续投票。
失败或无有效输出的结果不开启投票。

用户在渠道质量检测页的“质量评议”区查看本轮输出并投票。
检测结果按账号当前实际分组显示；原分组仍绑定时优先使用原分组，否则使用 ID 最小的有效当前分组。无有效当前分组的账号结果不向用户展示。将多个分组合并为一条策略不会把用户端分组标签合并；没有当前可见结果的分组不显示。历史分组汇总结果仍保留原分组，不代表新版仍支持创建该运行模式。

分组标签先按策略“显示顺序”排列，数值越小越靠前，`0` 有效；同一策略内按所选分组列表的上下顺序排列。账号移组后使用当前分组的展示位置。同组在多条策略中出现时取最靠前的位置，停用策略仍保留显示设置，没有对应策略的分组放在末尾。修改显示顺序后下次页面刷新即生效，无需重新检测，也不会重置本轮判定。

当前页面判定或投票后立即重新读取所属分组；其他页面的手动改组、定时检测改组通过每 5 秒一次的可见页面刷新同步，实际显示还需接口响应时间。切回页面或窗口重新获得焦点时立即刷新，无需等下一轮检测。分组标签、账号卡片和投票区一起更新，已过期的请求不会把账号移回旧分组；若新分组不再对用户开放，移除账号并关闭其已打开的历史记录。

只有有权查看实际展示分组的已登录用户可以投票。接口只公开账号 ID，不公开账号名称或自动化配置。账号移组后重新校验权限；如果有效投票本身导致投票人失去访问权限，仍提交该票及其动作，仅返回移组前已授权的信息。

## 自动暂停与手动停用

选择“检测自动暂停”后，账号状态显示 **检测自动暂停**，并记录原因。
普通请求不再调度该账号，管理员的“调度”开关保留原值。
选择“解除本规则的自动暂停”只清除该规则的暂停，所有规则的暂停原因均解除后才恢复。
选择“保持当前调度”不会清除既有暂停。

定时账号检测仅选择未删除、手动调度开关开启、状态为“正常”或“检测自动暂停”的账号。
在账号排队等待期间关闭调度，会在调用上游前再次检查。
手动关闭调度的账号不参与复测，不会被自动打开或自动调整分组；其他错误状态也不会被自动化覆盖。

正常结果列表隐藏自动暂停账号；独立投票区保留其新成功结果，供用户重新评议。
后台 OAuth 凭据续期继续运行，避免因检测暂停失去复测能力。

禁用、删除检测规则或修改保护条件时，会清理对应旧判定与投票资格。
如果没有其他暂停原因且手动调度仍开启，可解除该规则造成的暂停；仅修改名称或执行时间不会重置判定。

调整策略分组、模型、检测项目、判断条件或动作会使旧轮次失效，之后依据新范围重新检测。单独开关用户投票入口、修改名称、执行时间或显示顺序不重置本轮判定。停用策略期间不执行检测或接受投票；重新启用后按当时实际分组重新选择账号。关闭质量自动化、调整范围或删除策略均不会把已修改的账号分组静默改回。

同一个账号或分组不能由互相冲突的已启用切组策略管理。系统保存时检查冲突，执行时再次检查范围，防止账号后续增加分组导致重复检测或相互改组。

## 缓存率暂停后的自动试运行

统计规则可选择开启“缓存率暂停后自动试运行”，默认关闭。适用条件为：至少包含一个“缓存率小于”异常阈值、不包含“缓存率大于”阈值、不启用人工评议；不通过动作必须为自动暂停，通过动作必须为解除本规则暂停。若不通过动作还指定分组，目标仍须是策略内的非空分组，以便试运行接收正常请求。

- 冷却时间：60–86400 秒；系统每分钟检查是否到期。
- 试运行时长：60–3600 秒；本轮最多接入 1–1000 次正常请求尝试。
- 恢复最低样本数：1 到本轮请求额度之间；恢复缓存率不能低于任一暂停阈值，最高为 100%。

冷却结束后限量开放正常请求，只使用试运行开始后的新缓存样本判断恢复。同步请求和失败请求也消耗尝试额度，但不作为有效缓存样本。统计使用流式和 WebSocket 请求，并按输入 Token 加权；其他已配置统计条件也必须通过。

达到有效样本数及恢复条件后，仅解除本规则的暂停，并按本轮策略重新计算分组。试运行失败或到期时样本不足都会重新冷却，不会自动视为恢复。整个流程仍受手动停用、其他保护规则和必需自动条件约束，不会强制恢复被其他原因暂停的账号。

# 上游错误自动重试

在「系统设置 → 网关 → 上游错误自动重试」中开启，保存后生效，无需重启。默认关闭。

错误规则一行一个，任意一行命中即触发：

```text
503
server_is_overloaded
servers are currently overloaded
服务繁忙
```

纯数字按 HTTP 错误状态码精确匹配；文字对错误码、错误类型和错误提示做不区分大小写的包含匹配。例如 `currently overloaded` 可以匹配 `Our servers are currently overloaded. Please try again later.`。不需要通配符或正则表达式。JSON 响应仅匹配错误字段，不匹配回显的请求内容。

- 额外重试次数：1–10，默认 3；不含第一次请求。
- 重试间隔：100–10000 毫秒，默认 1000。
- 最多 100 行规则，每行最多 512 字节。
- HTTP 429 使用官方限流和重试策略，不受此配置影响。

HTTP 错误会在下发给客户端前重试；OpenAI Responses 的 SSE / WebSocket 错误只在尚未输出正文或工具调用、且可以安全重放时重试。已输出内容、已报告用量、客户端取消和无明确响应的网络错误不追加重试。不可重放的请求体也不在 HTTP 层自动重试。

HTTP 重试保持本次选中的账号、代理、请求头和请求体。流式错误沿用网关的并发释放与调度流程。一个客户端请求中的 HTTP 重试、流式错误重试与账号切换共享这项额外重试预算，预算用尽后交回原有错误处理。此功能可以减少临时上游故障导致的客户端重连，持续错误仍会返回给客户端。

配置保存在系统设置的 `upstream_error_retry` 字段，不需要数据库迁移。当前节点保存后立即生效，其他节点通过缓存刷新同步（最长约 60 秒）；已在重试的请求保留原有策略快照。

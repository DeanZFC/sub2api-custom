# 分组账号兜底

管理员在创建或编辑分组时配置“账号不可用时的兜底分组”。字段为 `fallback_group_id_on_unavailable`，默认不设置，更新时传 `0` 清除。只允许同平台的有效分组，不允许自身或循环引用；复合分组不支持此配置。

同一请求的顺序为：

1. 原分组选号，包括该分组全部严格主备层级。
2. 原分组没有可用账号时，尝试配置的分组兜底。
3. 两者均不可用时，尝试 API Key 已配置的兜底。

每次请求只尝试一级分组兜底，不继续展开目标分组的兜底配置。新请求总是先尝试原分组。数据库错误、状态未知或严格主备下的并发等待不属于“全部不可用”；不会因此切到下一分组。兜底目标的账号仍受模型能力、运行时状态、质量保护、严格主备和适用的利润控制检查。

## 两种计费

| 路径 | 账号来源 | 用户计费与用量归属 |
| --- | --- | --- |
| 普通请求 | 原分组 | 原分组 |
| 分组兜底 | 管理员配置的兜底分组 | 原分组的价格、倍率、用户覆盖、高峰配置及订阅；不需要用户另行订阅账号来源分组 |
| API Key 兜底 | API Key 配置的兜底分组 | 实际切换到的 API Key 兜底分组，沿用已有语义 |

分组兜底不会改写请求的 API Key 分组，异步用量快照保持原计费身份；账号成本仍记录实际使用的账号。利润准入使用本次真正收取的分组价格。调度日志中的 `billing_group_id` 与 `routed_group_id` 可用于区分两者。

普通网关和 OpenAI 兼容调度入口（含图片、Live 选号）共用兜底顺序。批量图片任务同样保留原分组价格快照和延迟结算归属。不可迁移的增量续接保持已有账号约束；严格主备的 WebSocket 续接在原分组恢复后要求携带完整上下文重连。

迁移 `330_group_unavailable_fallback.sql` 新增独立字段；认证缓存版本更新，管理员配置会进入实际认证查询和调度上下文。需部署匹配的前后端后生效。

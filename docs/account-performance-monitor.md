# 账号请求指标规则

入口：管理员账号列表 →「最近使用」中的成功率、缓存率、平均首字、平均耗时区域。点击整块指标区域配置该账号。没有请求记录也能进入配置。旧的 HTTP 错误率独立列和系统设置中的统计周期入口已经移除；分组零缓存保护及其 HTTP / WebSocket 拦截、采样和邮件通知均已移除。

## 统计与阈值

列表统计最近 1 小时全部日志，不受下方 10 条请求展示限制。所有实例读取同一数据库，并与规则评估复用同一聚合查询。

- 成功率：已记录成功请求 /（成功 + 失败）。按账号、API Key 和请求 ID 去重；终态失败覆盖同请求的部分输出。免费但有 Token 的成功请求计入，空的失败占位 usage 不计入成功。WS 连接错误单独计失败，不抹去已完成的 WS 轮次。
- 缓存率：成功流式 / WS 请求的缓存读取 Token / 文本提示 Token；排除图片输入，按 Token 加权。
- 平均首字：成功流式 / WS 请求的有效首字时间。
- 平均耗时：成功请求的有效总耗时。

排除赛博计费记录和错误日志中的 count_tokens；没有账号归属的错误不分摊给账号。统计依赖持久化日志，未写入日志的结果未知。缺失或负数耗时、缺失缓存数据不参与该指标；无样本为 `null`，真实零值有效。运维监控关闭时停止规则评估，配置弹窗显示指标未知，不能启用新规则；仍允许关闭或手动解除已有规则。

规则默认关闭。每项指标可填写「低于时暂停」「高于时暂停」，留空不参与；百分数使用 0–100，耗时使用毫秒。每 30 秒评估一次，任一指标样本达到设置值（默认 20）且严格越界即暂停，等于阈值不触发。

## 自动恢复

默认勾选自动恢复，但仅在启用规则后生效：

1. 暂停后冷却（默认 5 分钟，可配置 1–1440 分钟）。
2. 冷却到期开始试运行，每 5 秒最多准入一个正常业务请求，每轮最多放行恢复样本数的 3 倍。
3. 只检查本轮开始后的新样本。全部选中指标都达到恢复样本数（默认 3，可配置 1–100），且都在恢复上下限内，才解除暂停。
4. 任一指标达到恢复样本数后越过暂停阈值，或试运行 10 分钟仍未达标，重新暂停并进入下一轮冷却。

恢复阈值留空时沿用对应暂停阈值，也可以设置更严格的恢复条件，避免反复启停。没有流量、指标样本不足、旧样本过期都不算恢复。选择缓存率或首字条件时，必须有足够流式 / WS 请求产生对应指标。

试运行和恢复后的规则评估从本轮开始计数，最多回看 1 小时；弹窗显示实际参与评估的样本。列表仍显示完整最近 1 小时，旧失败因此可能仍显示在列表，但不会立即把刚恢复账号再次暂停。

准入限额存储在数据库，跨实例原子领取。无限并发、代理池和粘性候选也受最终准入门控制；后续并发检查拒绝时返还本次额度，使用配置版本和暂停代次隔离旧回调。

## 状态归属与升级

只修改独立规则表，不改管理员手动调度开关、账号状态、限流或其他暂停原因。在途请求继续执行。保存配置会清除此规则的暂停并重新评估；手动解除会同时关闭规则。自动恢复只解除本规则自身的暂停，管理员禁用的账号不会被自动启用。

新增迁移 `341_account_metric_rules.sql` 保留旧事件，记录 `retire`，禁用旧 HTTP 规则并清除其独立暂停。`342_retire_group_zero_cache.sql` 清理旧分组零缓存配置；旧 Redis 暂停不再被读取，其键按原 TTL 自然过期。没有修改已应用的迁移。升级后需在新入口重新配置阈值；旧进程采样器已删除。

保留管理员 API 的 `/accounts/performance` 批量读取、`/:id/performance` 保存、`/:id/performance/release` 解除及 `/:id/performance/events` 审计路径。配置使用 `version: 2`；保存校验 revision，解除还校验 pause_generation。配置、暂停、试运行、恢复和解除均在事务内写入事件，多实例评估使用行锁。

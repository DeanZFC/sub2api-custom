# 被动质量保护

日常配置统一在「渠道质量管理 → 分组质量」。旧版自定义规则及其编辑、升级和回放入口已删除，不能再创建或更新。

## 分组质量目标（全小时真实流量 + 主动恢复）

渠道质量管理 → 分组质量只需选择分组、设置四个指标并启用保护。新建目标默认缓存率 ≥80%、可用率 ≥90%、输出 TPS ≥30 token/s、首字 P90 ≤15 秒；已有策略的指标阈值保持不变，每项可以单独关闭。智力检测沿用已配置的主动计划：能力检测的暂停和恢复独立于这四项流量指标，任何一项保护解除都不能代替其他保护通过。

### 统计窗口与指标口径

全部分组目标统一使用 `recovery_mode=active`，按分组、账号、公开请求模型统计**滚动最近一小时内全部符合口径的已完成真实请求尝试**，不再取最近 100 条。`max_samples=0` 表示不按请求数量截断。数据在数据库内聚合，不把整小时请求明细无限加载到服务内存。目标生效或修改后的证据起点仍生效，不借用配置生效前的请求凑样本。

| 指标 | 计算口径 |
| --- | --- |
| 可用率 | 成功上游请求尝试数 ÷（成功 + 已确认失败尝试数）×100%；同一次尝试已记录失败时，不再把部分用量重复记为成功。它不是最终用户请求的成功率。 |
| 缓存率 | 有效文本缓存读取 Token 总数 ÷ 有效文本输入 Token 总数 ×100%，按 Token 加权，不是逐请求百分比的平均值。归一化存储口径的分母包含未缓存文本输入、缓存创建及缓存读取。 |
| 首字 | 有效流式/WS 请求首字时间的 P90；缺失首字时间不按 0 处理。 |
| 输出 TPS | 同一组有效流式/WS 样本的输出 Token 总数 ÷ 生成时长总秒数；生成时长 = 请求总时长 − 首字时间，不把等待首字时间算进输出速度。 |

明确上报的缓存零命中参与计算，缺失或无效缓存计数保持未知。图片 Token、compact 请求和非文本生成不进入缓存目标；生成媒体、compact、合成检测及缺失有效生成时长的请求不进入真实输出 TPS。不同指标有各自的有效样本数，不能拿请求总数代替缓存或速度样本数。

默认每个启用指标至少 **20 条有效样本**；后台约 **15 秒**评估一次。异常至少 **两次确认**，每次需要 **5 条对应指标的新增样本**，且完整窗口和新增证据都支持同一个指标异常。可用率异常证据需持续 **60 秒**，缓存、首字和 TPS 需持续 **300 秒**。等于阈值算达标。各指标分别累计，不能通过交替异常绕开确认；旧窗口很差但新增证据健康时不继续累积失败确认。连续证据中断超过窗口与 120 秒的较小值时重新计时，单纯等待不能凑出持续异常。

已确认的上游突发故障另有快速保护：启用可用率指标时，**最近 60 秒内连续至少 3 次失败**可直接暂停，防止一小时前的大量成功请求稀释当前不可用。它仍要求可核实的新失败证据；缺遥测、客户端取消或本地拒绝不能冒充上游失败。

### 暂停与主动恢复

四项启用指标中的任意一项持续异常确认后，暂停该账号模型调度；低缓存率不再只降低新会话分配。暂停期间不会放入客户请求做试运行，也不会通过全组应急兜底给受保护账号放行。没有合格可用供给时返回无可用渠道。人工停用、凭据、配额、并发、能力检测等准入仍独立生效。此处调整仅针对分组质量目标；独立统计类定时检测继续保留其连接探测和限量试运行机制。

系统首次评估一个已确定模型的账号且完全没有真实历史样本时，会先主动验证再调度；这不把缺样本当作质量失败。已有真实样本但尚不足确认的账号继续积累证据，缺样本本身不能证明异常。

首次暂停默认冷却 **5 分钟**，失败后递增退避，默认上限 **1 小时**。冷却到期后，系统定向调用相同账号和模型，使用系统生成的检测内容；不复制客户提示词。主动检测与已有质量检测共用预算和恢复预留，仍遵守执行资源及账号准入。预算不足、账号仍在冷却、缺少模型、请求形状不兼容或关键遥测缺失时保持暂停并记录等待原因，不当作检测通过。

主动请求按目标所属分组解析渠道模型映射，再由协议适配器应用账号模型映射，与业务请求使用相同映射顺序；统计、证据及暂停状态仍归属于公开请求模型。分组不明确、渠道映射暂不可用、映射目标为空或模型受渠道限制时，保留保护并显示对应等待原因，不跳过映射验证另一个模型。

检测前按已启用指标检查协议能力。当前 Bedrock、TypeSafe 测试适配器无法提供首字、输出 TPS 或缓存复用所需的完整证据；启用这些指标时返回 `active_probe_metrics_unsupported`，本轮不发送上游请求，保留保护并延后一小时复查条件，等待协议能力或配置更新。仅验证可用率不受此限制。未知指标不能按零值或通过处理，也不能反复发送已知无法取得有效证据的付费检测。

默认主动恢复至少 **两批**，每批每个启用指标至少 **5 条有效样本**，健康证据覆盖至少 **120 秒**。缓存开启时每批先发一条独立预热请求，再验证相同前缀的复用；预热计入请求数、可用率、时延和费用，但不参与缓存复用分母。不同批次使用不同测试前缀，避免只证明某个既有热缓存命中。默认单协议两批共 12 次请求；自适应账号保留各原生协议验证，双协议／三协议按有效实际尝试收批，分别约 16／18 次。本轮最多 20 次实际尝试，总运行超时 10 分钟。重试也计入实际尝试与检测预算。主动输出 TPS 要求最终用量和至少 128 个输出 Token；缺失最终遥测或短输出不能伪造成速度达标。

恢复要求**所有启用指标**同时达到恢复阈值，默认缓存 ≥85%、可用率 ≥95%、首字 P90 ≤12 秒、TPS ≥36 token/s。服务端结算会重新核验当前策略版本、执行租约、时间范围、批次数和每批证据。通过后只解除本策略的限制；能力检测或人工限制不会被顺带解除。记录页的“立即主动复测”只是申请检测，不能直接恢复调度。

主动恢复结果与真实流量一小时统计分开展示，保留系统请求数、预热数、批次、四项指标、原因、检测时间及恢复时间。主动请求不进入生产请求成功率、缓存率或速度统计，也不会把历史低质量记录刷掉。

恢复后保留完整的一小时历史展示，同时使用**恢复后新产生的请求证据**确认下一次异常，避免旧失败还在窗口内就立刻再次暂停。没有新证据时显示待样本。新的真实连续失败仍可触发快速保护；长期恢复后的健康证据才会清理异常退避，降低反复开关。

### 页面报告与边界

卡片的最近一小时指标来自定期真实请求报告，与暂停时的判定证据、主动恢复结果分开。报告正常约每分钟更新并显示生成时间；首个快照未生成或超过两分钟未更新时不标为当前达标。分组指标和账号/模型/用途贡献明细来自同一次数据库快照，明细最多展示 200 条并提示截断；此明细展示上限不截断全小时指标。无法归因的故障或缺少遥测不能证明健康。

主动缓存验证证明的是受控前缀下可复用，不保证真实客户提示词都适合缓存。冷启动、短提示词、客户输入变化和上游行为仍会使真实缓存率降低。该功能是质量筛选和恢复机制，不是未来每次请求都达标的承诺。

暂停门按账号 + 模型生效；跨组共用账号时，同一模型在其他组也会受限。不同服务等级应优先使用独立账号池。已建立的用户亲和继续稳定账号选择，确认暂停后才按实际可用候选迁移。

### 升级与旧路径移除

迁移 `321_group_quality_active_recovery.sql` 将现有 `group_quality_target` / `cache_target` 目标升级为主动恢复，保存旧配置审计归档，保留四项指标阈值、启停、模式、分组与账号排除。采样改为全小时不限条数，采用 20 个有效样本、5 个新增样本和两次确认的默认规则；稳定时间、冷却和主动恢复批次参数同步统一。原来的 `trial` / `probing` 转为暂停并等待主动检测，已存在的硬暂停不会被升级直接释放；旧客户试运行租约被移除，缓存软降分配投影被清理。人工状态和智力检测限制保持独立。

迁移 323 将全部分组目标收敛为主动恢复，归档原配置、使旧探测代次失效并清理客户试运行及应急兜底租约。服务端拒绝新的 recovery_mode=traffic 请求；前端不再提供恢复模式、客户验证配额或应急兜底配置。旧验证预算与兜底汇总接口字段一并删除；归档、历史用途及事件仅用于审计。

迁移执行前应备份数据库并协调多实例版本；归档不等同于自动回滚。迁移 305 的未知分组失败记录仍不猜测归属。

## 用户亲和与迁移

OpenAI 文本调度按**已认证用户、有效分组、公开请求模型**保存优先账号，活跃请求滚动续期 24 小时；同一用户的新会话优先复用该账号。既有会话绑定优先于用户偏好，`previous_response_id` 等不可重放上下文仍必须使用原账号。身份来自服务端认证上下文，不能通过请求正文冒充其他用户。媒体生成和 compact 专用请求不参与普通文本用户归属迁移。

负载或调度偏好小幅变化或单次首字变慢不再绕过分组质量的持续确认来重新分配已有用户。账号确认被自动质量暂停或其他持久准入失效后，替代账号通过最终并发、利润和其他准入再迁移正常会话及用户归属；原账号恢复不会自动拉回已迁移会话。并发拥堵和利润临时不适合属于借用，不改原归属。Redis 条件更新阻止较早请求完成后覆盖较新的归属；首次并发建会话仍是尽力一致，不能承诺所有同时开始的会话绝对同号。

分组质量及智力检测自动暂停账号不参与客户应急放行。正常 API Key 备用分组与质量保护独立，仍可按原有配置寻找通过全部准入的健康供给；备用分组也不能绕过账号或模型的自动暂停。人工停用、凭据失效、配额、模型能力及真实请求失败仍可导致切换。稳定账号减少本系统造成的缓存碎片，但不保证上游一定复用缓存。

## 记录与管理

状态和事件在服务端筛选并按游标分页；状态支持分组目标、账号、模型、阶段，事件额外支持类型和时间范围。全局汇总独立于分页，缺失指标显示未知。人工停用、智力检查暂停和其他硬限制独立生效。

仅改名或原样保存保留分组目标的已有证据、冷却与恢复进度。改变阈值、范围、启停或稳定性参数等保护行为才重新积累本目标的证据。旧配置缺少 `stability` 时在运行时使用默认值；编辑器展开相同默认值后原样保存不重置证据。历史旧规则事件仍可只读查询。

## 升级移除旧规则

迁移 `318_retire_custom_passive_rules.sql` 将全部非分组目标规则归档到 `quality_management_config_archive` 的 `passive_retired` 类别，然后删除旧规则、对应暂停状态及试运行租约，并刷新受影响账号的调度缓存。无论旧规则是否启用、是否覆盖已有目标分组，都会移除。数据库约束和管理 API 阻止旧客户端重建规则。

`group_quality_target` 和早期 `cache_target` 均为有效分组目标，其配置、证据和暂停保留。手动停用、智力检查及其他保护不受影响；仅由旧规则暂停的账号解除旧限制。没有分组目标的组需在分组质量中配置目标，不会自动套用新阈值。

旧规则的移除不可通过回退二进制恢复；安装前备份数据库并协调多实例升级。归档用于审计，不是完整状态恢复备份。

# 被动质量保护

日常配置统一在「渠道质量管理 → 分组质量」。旧版自定义规则及其编辑、升级和回放入口已删除，不能再创建或更新。

## 分组质量目标（实际请求）

渠道质量管理 → 分组质量提供简化配置：选择分组，设置缓存率、可用率、输出 TPS 和首字 P90，再启用保护。所有新建分组默认缓存率 ≥80%、可用率 ≥90%、TPS ≥30 token/s、首字 P90 ≤15 秒；已有策略阈值保持不变。每个指标可以单独关闭。智力检测入口继续使用已有主动计划，支持鹈鹕生成与人工评审、总耗时、糖果答案和模型一致性。

该功能使用 `purpose=group_quality_target` 的独立策略，按分组内实际出现的每个模型分别维护账号状态，采用实际上报的文本缓存 token 比率，不要求上游具有已证明的可复用缓存作用域。缺失计数不会伪造成缓存命中。缓存率按 token 加权，明确上报的零命中也是有效样本；图片 token、压缩请求和非文本生成请求不用于缓存目标。首字使用流式/WS 请求的 P90；可用率统计该分组完成的上游请求尝试，失败优先于同一次尝试的部分用量，不能与最终用户请求成功率混用。

默认每个账号模型回看 **1 小时/最多 100 条**，每个指标至少 **5 条有效样本**，后台约 **15 秒**检查一次。至少 **两次确认**且每次增加 **2 条对应指标样本**，同时满足异常持续时间，才确认持续异常：可用率默认 **60 秒**，首字和输出速度默认 **300 秒**。等于目标值算达标；时间按新证据的时间戳推进，不能反复读取旧窗口、单纯等待或跨越无证据间隔凑时长。普通流量超过策略窗口与 120 秒中的较短间隔没有连续证据时重新计时；恢复试运行会按限量请求的节奏放宽证据间隔，并保留覆盖恢复持续时间的样本窗口。

性能初次异常先将该模型的新会话分配采样比例降至 **20%**，已有会话和已有用户亲和不受这项软限制影响。该比例是候选采样比例，不是固定流量配额；没有其他可用候选时仍保留服务能力。**单纯低缓存率始终只限制新分配，不暂停已有会话或强制切号**。实际缓存率包含冷启动和不可复用的工作负载，不能证明账号缓存故障。缓存持续异常达到 300 秒后记录持续降分配原因；缓存窗口及新增样本都达到恢复阈值（默认 85%），并经多批证据持续默认 120 秒后，才恢复新分配。可用率、首字和输出速度独立判定，低缓存率不会遮挡其他指标的真实异常。

硬指标确认异常后首次冷却 **5 分钟**，只开放限量真实流量试运行（默认并发 1、最多 20 次、15 分钟）。恢复需要所有启用的可用率/首字/TPS 指标有足够有效样本，并由多批新健康证据覆盖至少 **120 秒**；低缓存率可继续软限制新分配，不阻塞硬指标恢复。试运行将一部分请求额度分散到恢复时段，避免短时突发耗尽全部验证机会。旧策略试运行时长过短时，有效窗口至少为恢复时长与确认次数所需检查时间（每次预留 30 秒）中的较大值，再加 120 秒，次数和并发上限不增加。冷却到期不能代替真实达标。可用率恢复门槛默认比目标高 5 个百分点，TPS 默认恢复为 36 token/s，首字恢复门槛为上限的 80%。

试运行恢复批次和确认次数会根据有限请求额度自动折算，使新旧配置都能在原请求上限内完成至少两批恢复确认；普通异常确认仍按原配置执行。

试运行成功不立即清零异常退避；再次异常沿用递增冷却，直到持续 **10 分钟**的新健康证据才重置，降低“开—关—开”振荡。缺样本或缺遥测只等待，不伪造成恢复或新的失败。手动停用和其他检测的暂停仍独立有效。

首次异常由完整窗口建立待确认状态，后续确认要求同一指标的新增样本本身也达到异常阈值；旧异常仍在窗口内、但新到样本健康时不会继续累计确认。切换异常指标、出现新增健康证据或证据过期会重置对应确认与计时，未知指标不按零处理。页面分别显示完整窗口与新增证据的指标值和有效样本数；这项新增异常确认规则仅适用于分组质量目标。

卡片上的最近 1 小时指标来自后台定期生成的真实请求报告，与暂停时保留的判定证据分开。报告正常约每分钟更新，显示窗口和生成时间；首个快照未生成或超过两分钟未更新时不判为当前达标。分组指标、流量统计与账号/模型/用途贡献明细来自同一次数据库快照，明细最多展示 200 条并提示截断；无法关联请求用途时显示未归因。没有样本、缓存计数缺失、故障采集缺口，或升级前无法归属分组的失败记录，都不能证明达标；页面显示待样本/未知。原有低质量请求不会被清空，历史滚动指标需要随真实流量变化。

这是质量筛选与自动恢复目标，不是对未来请求的数学保证。冷启动、新模型、低样本、上游变化和限量恢复流量可能暂时拉低分组统计。如果所有账号均不合格，保护状态与缺少已验证供给的提示仍保留；OpenAI 分组可按[全组评分兜底](channel-quality.md#全组按评分兜底)为单次请求取得许可，仍须通过人工状态及其他硬性准入，不代表账号已恢复达标。暂停门目前按账号+模型生效；跨组共用账号会同时受到影响，其他组流量也可能消耗该账号模型的试运行预算。需要不同服务等级时，优先使用独立账号池。

升级迁移 305 为失败证据新增 `group_id` 与索引；旧记录保留 0（未知），不猜测归属。迁移是增量兼容的；升级前仍应备份生产数据库。

## 用户亲和与迁移

OpenAI 文本调度按**已认证用户、有效分组、公开请求模型**保存优先账号，活跃请求滚动续期 24 小时；同一用户的新会话优先复用该账号。既有会话绑定优先于用户偏好，`previous_response_id` 等不可重放上下文仍必须使用原账号。身份来自服务端认证上下文，不能通过请求正文冒充其他用户。媒体生成和 compact 专用请求不参与普通文本用户归属迁移。

负载/评分小幅变化或单次首字变慢不再绕过分组质量的持续确认来重新分配已有用户。账号确认被自动质量暂停或其他持久准入失效后，替代账号通过最终并发、利润和其他准入再迁移正常会话及用户归属；原账号恢复不会自动拉回已迁移会话。并发拥堵、临时验证预算不足和利润临时不适合属于借用，不改原归属。Redis 条件更新阻止较早请求完成后覆盖较新的归属；首次并发建会话仍是尽力一致，不能承诺所有同时开始的会话绝对同号。

全组应急兜底优先沿用仍可准入的会话及用户归属，确认失效后的替代账号也在最终准入后条件更新；正常供给恢复时，应急账号若仍被保护，可回归正常路由。缺少可用用户亲和时，沿用 API key/分组/模型/会话的独立 30 分钟兜底偏好。人工停用、凭据失效、配额、模型能力及真实请求失败仍可导致切换。稳定账号减少本系统造成的缓存碎片，但不保证上游一定复用缓存。

## 记录与管理

状态和事件在服务端筛选并按游标分页；状态支持分组目标、账号、模型、阶段，事件额外支持类型和时间范围。全局汇总独立于分页，缺失指标显示未知。人工停用、智力检查暂停和其他硬限制独立生效。

仅改名或原样保存保留分组目标的已有证据、冷却与恢复进度。改变阈值、范围、启停或稳定性参数等保护行为才重新积累本目标的证据。旧配置缺少 `stability` 时在运行时使用默认值；编辑器展开相同默认值后原样保存不重置证据。历史旧规则事件仍可只读查询。

## 升级移除旧规则

迁移 `318_retire_custom_passive_rules.sql` 将全部非分组目标规则归档到 `quality_management_config_archive` 的 `passive_retired` 类别，然后删除旧规则、对应暂停状态及试运行租约，并刷新受影响账号的调度缓存。无论旧规则是否启用、是否覆盖已有目标分组，都会移除。数据库约束和管理 API 阻止旧客户端重建规则。

`group_quality_target` 和早期 `cache_target` 均为有效分组目标，其配置、证据和暂停保留。手动停用、智力检查及其他保护不受影响；仅由旧规则暂停的账号解除旧限制。没有分组目标的组需在分组质量中配置目标，不会自动套用新阈值。

旧规则的移除不可通过回退二进制恢复；安装前备份数据库并协调多实例升级。归档用于审计，不是完整状态恢复备份。

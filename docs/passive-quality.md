# 被动质量保护

日常配置统一在「渠道质量管理 → 分组质量」。旧版自定义规则及其编辑、升级和回放入口已删除，不能再创建或更新。

## 分组质量目标（实际请求）

渠道质量管理 → 分组质量提供简化配置：选择分组，设置缓存率、可用率、输出 TPS 和首字 P90，再启用保护。所有新建分组默认缓存率 ≥80%、可用率 ≥90%、TPS ≥30 token/s、首字 P90 ≤15 秒；已有策略阈值保持不变。每个指标可以单独关闭。智力检测入口继续使用已有主动计划，支持鹈鹕生成与人工评审、总耗时、糖果答案和模型一致性。

该功能使用 `purpose=group_quality_target` 的独立策略，按分组内实际出现的每个模型分别维护账号状态，采用实际上报的文本缓存 token 比率，不要求上游具有已证明的可复用缓存作用域。缺失计数不会伪造成缓存命中。缓存率按 token 加权，明确上报的零命中也是有效样本；图片 token、压缩请求和非文本生成请求不用于缓存目标。首字使用流式/WS 请求的 P90；可用率统计该分组完成的上游请求尝试，失败优先于同一次尝试的部分用量，不能与最终用户请求成功率混用。

默认每个账号模型回看 1 小时/最多 100 条，至少 5 条有效指标样本，后台约每 15 秒检查，连续两次确认且每次增加至少 2 条对应指标样本后暂停。等于目标值算达标。首次冷却 5 分钟后只开放限量真实流量试运行（默认并发 1、最多 20 次、15 分钟），各项启用指标均有足够新样本并达到恢复门槛后才恢复；冷却到期不能代替真实达标。缓存/可用率恢复门槛默认比目标高 5 个百分点，TPS 默认恢复门槛为 36 token/s，首字恢复门槛为上限的 80%。失败再次冷却，手动停用和其他检测的暂停仍独立有效。

首次异常由完整窗口建立待确认状态，后续确认要求同一指标的新增样本本身也达到异常阈值；旧异常仍在窗口内、但新到样本健康时不会继续累计确认。切换异常指标或证据过期会重置确认，未知指标不按零处理。页面分别显示完整窗口与新增证据的指标值和有效样本数；这项新增异常确认规则仅适用于分组质量目标。

卡片上的最近 1 小时指标来自后台定期生成的真实请求报告，与暂停时保留的判定证据分开。报告正常约每分钟更新，显示窗口和生成时间；首个快照未生成或超过两分钟未更新时不判为当前达标。分组指标、流量统计与账号/模型/用途贡献明细来自同一次数据库快照，明细最多展示 200 条并提示截断；无法关联请求用途时显示未归因。没有样本、缓存计数缺失、故障采集缺口，或升级前无法归属分组的失败记录，都不能证明达标；页面显示待样本/未知。原有低质量请求不会被清空，历史滚动指标需要随真实流量变化。

这是质量筛选与自动恢复目标，不是对未来请求的数学保证。冷启动、新模型、低样本、上游变化和限量恢复流量可能暂时拉低分组统计。如果所有账号均不合格，保护状态与缺少已验证供给的提示仍保留；OpenAI 分组可按[全组评分兜底](channel-quality.md#全组按评分兜底)为单次请求取得许可，仍须通过人工状态及其他硬性准入，不代表账号已恢复达标。暂停门目前按账号+模型生效；跨组共用账号会同时受到影响，其他组流量也可能消耗该账号模型的试运行预算。需要不同服务等级时，优先使用独立账号池。

升级迁移 305 为失败证据新增 `group_id` 与索引；旧记录保留 0（未知），不猜测归属。迁移是增量兼容的；升级前仍应备份生产数据库。

## 记录与管理

状态和事件在服务端筛选并按游标分页；状态支持分组目标、账号、模型、阶段，事件额外支持类型和时间范围。全局汇总独立于分页，缺失指标显示未知。人工停用、智力检查暂停和其他硬限制独立生效。

仅改名或原样保存保留分组目标的已有证据、冷却与恢复进度。改变阈值、范围、启停等保护行为才重新积累本目标的证据。历史旧规则事件仍可只读查询。

## 升级移除旧规则

迁移 `318_retire_custom_passive_rules.sql` 将全部非分组目标规则归档到 `quality_management_config_archive` 的 `passive_retired` 类别，然后删除旧规则、对应暂停状态及试运行租约，并刷新受影响账号的调度缓存。无论旧规则是否启用、是否覆盖已有目标分组，都会移除。数据库约束和管理 API 阻止旧客户端重建规则。

`group_quality_target` 和早期 `cache_target` 均为有效分组目标，其配置、证据和暂停保留。手动停用、智力检查及其他保护不受影响；仅由旧规则暂停的账号解除旧限制。没有分组目标的组需在分组质量中配置目标，不会自动套用新阈值。

旧规则的移除不可通过回退二进制恢复；安装前备份数据库并协调多实例升级。归档用于审计，不是完整状态恢复备份。

## 启用入口

- **系统设置 → 网关 → Codex 打票**：默认关闭。配置模型、采集分组、代理来源、固定/备用策略及缺票阻断。
- **Codex 打票管理**（`/admin/harvest-flow`）：查看账号门票摘要、采集进度、节点历史，调整并行采集控制，执行手动采集和账号跳过采集。
- **IP 管理 → 订阅/动态代理/节点/内核**：管理 Mihomo 与国家过滤。页面加载不会自动安装或启动内核。
- **账号新增/编辑/批量编辑 → Excel / BPS**：仅适用于原有 OpenAI OAuth 账号，默认关闭，使用原账号凭据刷新链路。
- **系统设置 → 功能 → Excel / BPS 图片**：默认关闭，可选 relay/native 及容量、图片和有效期限制。

## 路由与兼容

- 票据按账号和实际出站模型匹配。缺票阻断与严格响应检查均为显式开关，默认关闭；跳过采集的账号仍可正常使用。
- 已绑定的票据会固定其采集身份与出口，HTTP/WS 在退出时释放节点租约。发送前检查当前账号状态，配置变更后拒绝沿用旧身份和路由。
- 保留现有 VM 转发和凭据影子功能；它们不参与原生账号门票门控。绑定票据的原生请求直接使用受控传输。
- BPS 可指定模型范围：未保存范围字段表示旧版全模型模式，显式空列表表示不选任何模型。范围外模型继续原有协议。
- 选中的 BPS 模型使用 HTTP/SSE，WebSocket 请求应改用 HTTP。BPS 失败不会静默改成原生协议，也不会在通用 HTTP 重试器中自动重放。
- 账号连接测试与现有定时测试遵循相同的模型通道，保留 VM 优先级，回收实际返回模型、用量、预算和首 token 时间。
- 可单独启用省略不支持工具、历史图片、加密历史，以及缓存写入按普通输入计费；默认关闭。后者只影响实际 BPS 请求。
- 403 自动停用 BPS、迁移分组均须主动开启；账号凭据和当前配置在数据库锁内复核，避免并发覆盖。

## 部署与数据

- 新增 `334_restore_codex_ticket_harvesting.sql`。保留已应用迁移的文件内容与 SHA；升级由现有迁移器创建节点学习和流程记录表。生产安装前须备份数据库，多实例协调升级；镜像/源码回退不会撤销已执行迁移，恢复数据库需使用经过核验的备份。
- 旧的账号级 `codex_ticket_*` 开关不再生效。新功能使用系统级配置，旧票据和被历史迁移删除的记录不会恢复。
- 原始票据、Cookie、带凭据的旧采集代理不会出现在账号 DTO 或账号导出中。管理端仅展示票据状态摘要，禁止导入伪造票据。
- 这些管理接口沿用管理员认证与审计；受限管理密钥不会自动得到新接口权限。
- 内置 Mihomo 的安装/运行支持 Linux amd64/arm64，数据位于现有数据目录的 `mihomo-codex`；其他系统可编译并使用其余功能，但无法本地安装托管内核。
- relay 图片需要配置能被上游访问的外部地址，图片访问凭短期能力令牌授权，并受大小、数量和有效期限制。
- 上游账号权限、模型资格、额度及出口实际公网 IP 仍取决于上游和代理服务；本次合并不保证真实上游采集或调用成功。

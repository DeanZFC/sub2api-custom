# 账号保护

在「账号管理 → 编辑账号 → 账号保护」中启用。设置直接作用于已有账号，无需重新导入。新建、导入或复制账号不会自动开启此功能，也不会继承其他账号的保护快照。

## 默认行为

默认选择与参考版本 `PrepareNewAccountProtection` 相同的策略，但由管理员明确开启：

| 账号情况 | 默认策略 | 作用 |
| --- | --- | --- |
| 独立 OpenAI OAuth / Setup Token，固定代理或直连 | 初代兼容 `legacy` | 稳定账号会话身份，使用 Node.js 24 TLS 模板 |
| 独立 Anthropic OAuth / Setup Token，固定代理或直连 | 初代兼容 `legacy` | 使用 Node.js 24 TLS 模板，保留 Anthropic 协议 |
| API Key、其他平台、影子账号或多代理账号 | 通用并发保护 `generic` | 仅设置正数并发上限，保留原身份、TLS、协议与代理选择 |

已经设置的正数并发不会因默认策略而改变；例如并发 3 仍为 3。未设置有效上限时，默认策略使用 16。开启后仍可修改正数并发。

OpenAI 身份保护支持 `legacy`、`mode1`、`mode2`、`minimal_compat`、`session_standard`、`tls_node24`、`low_concurrency`、`single_machine_multi_window`。策略差异可在账号弹窗查看。身份策略要求固定代理或直连，切换策略直接生效。

## 保存与还原

- 首次开启记录原始配置，切换策略不会把上一个策略误当作原始配置。
- 关闭身份保护恢复其管理的身份与传输设置；通用保护不还原或覆盖它未管理的字段。
- 后续手动调整的并发保留；普通保存、局部更新和批量更新不能覆盖保护标记。
- 账号配置在操作期间发生变化时会返回冲突，刷新账号后再执行即可。
- 保护字段随调度缓存同步；WebSocket 连接复用会区分策略、实际 TLS 配置、代理、地址和会话。
- 已有 mode1 v2 配置保留原传输行为，可在同一入口显式升级 v3；升级保留原始快照、身份种子和当前并发。

## 与其他功能的关系

自适应并发、账号健康和渠道测试保持独立配置。身份保护不会自动启用这些功能，也不会创建另一套智能测试队列。现有手动账号测试和渠道测试会使用所测账号当前的身份与传输策略；测试失败不作为生产请求参与自适应并发统计。

账号健康默认关闭。其自动隔离只对明确允许自动控制的账号生效，数据库写入会复验当前开关及冷却状态；自动恢复只清理自动健康隔离，不清理手动隔离或官方限流状态。

## 验证边界

策略名称描述本地身份与传输配置，不代表上游已确认使用某种设备，也不保证模型质量。实际 TLS 仍受全局 TLS 开关影响；明确绑定插件的账号继续遵循插件路由配置。

上线后可用同一账号、模型、提示词与推理强度，在关闭和开启策略时分别执行渠道测试。比较完整输出、耗时和稳定性，同时检查真实业务请求；单次输出不能证明模型质量提升。

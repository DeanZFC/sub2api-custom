# GPT 直充接入

Sub2API 提供购买入口及原生兑换页面，CTAI-GPT 负责 CDK、任务队列和实际充值。两套服务需要同时运行；本站余额兑换码与 GPT 直充 CDK 独立。

## 配置

打开 **系统设置 → GPT 直充**，填写并点击 **保存直充设置**（此页独立保存）：

首次配置预填服务地址 `https://ctai.chengtingkj.org`、购买链接 `https://wzyp.cn/shop/ctai/mgitov` 和渠道 `ctai`，功能默认关闭。所有字段均可在后台修改，升级不会覆盖已经保存的配置或显式清空的地址。

- **CTAI-GPT 服务地址**：填写 Sub2API 后端能够访问的根地址，例如 `https://recharge.example.com`。允许带端口，不带 `/ctai/gpt`、`/api/v1`、查询参数或用户密码。
- **渠道标识**：主站使用 `ctai`，代理渠道使用其专属链接中的 slug。购买链接出售的 CDK 必须属于该渠道和 GPT 产品。
- **购买 CDK 链接**：用户点击后在新标签页打开。
- **购买按钮文字、购买说明**：选填。
- **客服信息**：选填，支持 QQ、微信、说明等多行文字，最多 2048 字；填写完整 HTTP/HTTPS 网址时显示为可点击链接。已有客服网址继续保留。
- **启用 GPT 直充**：默认关闭；启用时服务地址和购买链接必填。开启后用户侧及管理员“我的账户”区域显示入口 `/gpt-direct`。
- **直充成功赠送抽奖机会**：默认关闭；开启后填写每笔赠送次数（1–1000），例如填写 `1` 表示每成功直充一笔赠送一次 QQ 抽奖机会。在 QQ 机器人中开启抽奖并配置奖池后，用户可绑定 QQ 并在群内发送 `/抽奖` 使用。

不需要 CTAI 管理员账号或管理员 API Key。普通用户不会收到服务地址或渠道配置，也不会向 CTAI 转发 Sub2API 登录 Token、Cookie 或原始浏览器请求头。

## 保留上游按客户端 IP 限流

Sub2API 保留本地按用户的面板限流，并通过可信客户端 IP 解析结果构造单个 `X-Forwarded-For`。CTAI-GPT 现有 `TRUSTED_PROXY_CIDRS` 配置需要仅信任 Sub2API 的实际出口 IP/CIDR 和必要的反向代理地址。例如同机容器部署时，应根据实际网络指定对应地址，不能照抄公网示例，也不能设为全网可信。

CTAI 前置反代应保留并正确追加 `X-Forwarded-For`，且不要信任任意外部来源伪造的转发头。未配置可信代理时，CTAI 会把所有转发请求按服务器 IP 合并计数；并发用户可能一起触发上游限额。出现 429 时，接口保留 `Retry-After`，进度轮询自动退避。

## 用户流程及恢复

购买 CDK → 验码 → 填写 ChatGPT Session → 查询账号/订阅 → 确认兑换 → 查看进度。若当前订阅查询暂不可用，用户需明确确认自行核对的账号后才能继续；可识别的无效或过期凭据会拦截。

Session 输入框标题旁提供“获取 Session”链接，在新标签页打开 ChatGPT Session 页面。先登录需要充值的 ChatGPT 账号，再复制 Session 内容回到本页填写。

兑换写请求不会自动重试，也不会跟随上游重定向。相同 CDK 的未确认提交在本标签页刷新后沿用原请求编号，并按 Sub2API 用户隔离请求编号。提交超时时先查 CDK 状态；不要盲目更换账号重交。任务成功、失败、取消后停止自动轮询；后台标签页暂停轮询。

浏览器 sessionStorage 仅保存任务 ID、任务查询凭据，以及未确认提交的请求编号和 CDK 哈希，按用户和服务/渠道隔离。CDK、账号 Session 和邮箱不会写入本页的浏览器存储。关闭标签页、禁用浏览器存储或换设备后，可凭原 CDK 查询状态。

Sub2API 对该功能的请求体整体排除审计存储，返回数据按字段白名单筛选，错误信息不会透传上游诊断。CTAI-GPT 按其既有流程处理和保存充值任务所需的凭据。

## 直充赠送抽奖机会

奖励归属提交直充时登录的网站账号，无需事先绑定 QQ。后台“QQ 机器人 → 抽奖”的用户次数查询会显示累计次数和其中直充赠送次数；原有余额充值送次数、奖池和保底规则继续生效。

每次提交先保存奖励规则快照；后续调整赠送次数或关闭功能不会改变已提交订单的快照，也不会补发历史订单。只有 Sub2API 实际收到并记录的 CTAI 兑换回执才参与发放；输入 CDK 查询状态或持有别人的任务查询凭据不能领取奖励。同一服务、渠道和 CDK 的奖励有唯一约束，重复查询、刷新、换请求编号以及多个实例并发均不会重复赠送。

成功状态与赠送流水在一个数据库事务中落库。服务重启或用户关闭页面后，后台继续查询已登记任务；失败、取消时不发放，并每小时复查一次，持续最多 30 天，以覆盖人工重试后成功的情况。后台不自动重发兑换请求。若上游已受理但响应超时，使用原 CDK、原账号 Session 和原请求编号重试恢复回执后可继续跟踪；未收到回执的请求不能仅凭 CDK 状态自动认领奖励。

开启赠送要求配置固定的 `TOTP_ENCRYPTION_KEY`，沿用项目现有密钥保护任务查询凭据。数据库仅保存 CDK 哈希、所属账号、规则快照和加密的任务查询凭据，不保存 ChatGPT Session。奖励成功发放后清除加密查询凭据；失败或取消的任务在复查期结束后也清除。请勿随意更换加密密钥。两个服务的时钟应保持同步，以识别历史回执。

迁移 `279_gpt_direct_lottery_rewards.sql` 会创建直充跟踪和抽奖次数赠送表。直充次数与原有按余额充值计算的次数合并使用，不能把活动奖品再当作充值本金重复产生机会。

## 验证边界

本地测试使用模拟 CTAI HTTP 服务和模拟页面接口，不调用实际充值或支付。部署后应先核对公开配置、菜单、购买链接、渠道匹配及代理限流；真实 CDK 兑换会触发实际业务，应单独安排验收。

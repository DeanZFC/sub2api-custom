# Codex 打票诊断

内置打票支持注入缺失统计和近期采票历史，292/332 门票均使用账号自身的出口。

## 有效期与路由 Cookie

292 门票按约 240 秒有效窗口处理，默认提前 60 秒续票。`gateway.openai_codex_ticket.ttl_seconds` 默认及上限均为 240；更短的正数配置继续有效。`refresh_before_seconds` 默认 60，最多为配置 TTL 的四分之一。旧配置如 `3600/600` 或 `3600/300` 会自动归一为 `240/60`，避免继续注入长寿命旧票或因提前刷新时间过大而连续打票。292/332 共用该保守的时间上限；这不代表已确认 332 的上游寿命也缩短。

292 请求同时需要有效的 `__cflb` 和 `__oailb` 路由 Cookie。服务自动从采票响应的 `Set-Cookie` 获取并续期，按账号在模型间共享，不跨账号共享，也不要求用户手填。Cookie 自身过期可能早于票据；292 的可用状态和剩余时间以两者中较早失效的一方为准。编辑账号中的诊断会显示路由 Cookie 可用状态和剩余秒数，不显示 Cookie 内容。332 暂不强制要求这两个 Cookie。

仅有 292 票据、缺少有效 Cookie 时不视为可用。账号启用“缺票时禁用模型”后会暂停对应模型；关闭此开关则继续放行请求并后台采票。旧存量 292 门票需要重新获取有效 Cookie 后才能恢复为可用。

HTTP 请求和 WS 新握手都会注入当前有效的票据与 Cookie。WS 连接池按两者的摘要区分连接，续票后新请求不会复用旧凭据建立的连接；等待连接或预热延迟期间也会重新检查有效期。受管理的 WS 会话在下一轮携带完整输入、没有续链 ID 和工具结果依赖时可重新握手续票。依赖 `previous_response_id` / 工具结果的活跃连接及透明 WS 透传连接暂不自动强制换连，因此不能保证超过约 240 秒的这类长会话无损续票；需要稳定跨窗口续票时可使用 HTTP 或 `http_bridge` 模式。

## 打票出口

系统设置 → 网关 → Codex 打票保留总开关，账号管理中保留账号启用和缺票禁用模型开关。

每次打票均使用账号配置的业务代理；未绑定代理的账号使用直连。已绑定的代理信息缺失或无效时暂停采票，不自动改为直连或其他代理。连接失败、超时、代理认证失败和上游错误只按既有规则退避重试，不自动切换出口。

账号的所有模型使用同一账号出口。修改账号代理后，旧打票请求会取消，等待其释放后使用新代理。全局、账号及相同出口的并发限制和冷却继续生效。

网关代理池、代理来源选择和独立打票代理出口测试已移除。旧数据库、YAML 或环境变量中的打票代理池配置不再影响采票。若账号代理供应商会轮换公网 IP，使用同一个代理地址仍不能保证每次公网 IP 相同。

## 账号统计与历史

账号管理 → 编辑 OpenAI OAuth 账号 → Codex 打票。每个配置模型分别显示采票成功、失败、注入缺失次数，以及最近一次注入缺失时间。账号列表仅返回轻量统计。

- 成功和失败按实际完成的采票请求计数；等待代理或因代理并发已满而跳过，不增加次数；取消单独记录，不计为失败。
- 注入缺失只统计已进入出站注入步骤、却没有有效门票的请求。调度阶段因缺票禁用模型而排除的账号不计入，因此零缺失不代表所有账号均有票。
- 点击“采票历史”按需加载最新 20 条；支持手动刷新，不自动轮询。记录包含时间、结果、固定错误分类、HTTP 状态、票据长度、目标长度、出口来源及耗时，不包含票据内容、代理密码或上游原始响应。
- 统计和历史仅保存在当前服务进程内。重启清零；关闭打票、移除账号或模型后会清理。多实例各自记录。

以上诊断沿用内置采票和指纹逻辑，不需要安装传输插件。

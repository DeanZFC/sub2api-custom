# Codex 打票诊断

从 `v0.2.7-custom.1` 起，内置打票支持注入缺失统计、近期采票历史和代理出口测试。

## 账号统计与历史

账号管理 → 编辑 OpenAI OAuth 账号 → Codex 打票。每个配置模型分别显示采票成功、失败、注入缺失次数，以及最近一次注入缺失时间。账号列表仅返回轻量统计。

- 成功和失败按实际完成的采票请求计数；等待代理或因代理并发已满而跳过，不增加次数；取消单独记录，不计为失败。
- 注入缺失只统计已进入出站注入步骤、却没有有效门票的请求。调度阶段因缺票禁用模型而排除的账号不计入，因此零缺失不代表所有账号均有票。
- 点击“采票历史”按需加载最新 20 条；支持手动刷新，不自动轮询。记录包含时间、结果、固定错误分类、HTTP 状态、票据长度、目标长度、代理编号及耗时，不包含票据内容、代理密码或上游原始响应。
- 统计和历史仅保存在当前服务进程内。重启清零；关闭打票、移除账号或模型后会清理。多实例各自记录。

## 代理出口测试

系统设置 → 网关 → Codex 打票代理池。先保存多行代理配置，再选择代理编号并点击出口测试。编号对应服务端解析、去除空行和重复地址后的代理池顺序。

测试只使用选中的已保存代理，请求固定的 `https://api64.ipify.org?format=json`，返回公网出口 IP 和耗时；不携带账号凭据、不跟随重定向、失败不回退直连。最多同时测试两个代理，同一代理不重复启动，单次最长 10 秒。

出口测试成功只证明该代理能访问 IP 查询服务，不能证明它能访问模型服务或成功取得 292/332 门票。实际采票结果请看账号历史。

以上诊断沿用内置采票和指纹逻辑，不需要安装传输插件。

# Mihomo 与打票更新说明（2026-11-04）

本轮按功能合入 ranxi2001/sub2api `981f3645a6df2a099b8dde1acdbbb8a77875a68a` 的 Mihomo 与票据采集更新，并适配当前自定义版的 VM、PAT、Agent Identity、影子账号与独立 Excel 授权边界。

## 打票总开关

在「系统设置 → 功能开关 → Codex 打票功能」开启并保存后，才显示侧栏打票管理、网关设置的打票快捷入口、自动策略、号池调度、采票出口和 Mihomo 的打票专用操作。默认关闭，未加载或缺少设置时也不显示。直接访问打票管理地址会跳转到功能设置；已打开的页面在开关关闭后收起功能并停止轮询。

该开关复用既有的 `openai_codex_ticket_enabled`，同时控制打票运行，无需再开启另一个菜单开关。已有数据库或 YAML/env 中明确开启的配置继续生效。常规代理、Mihomo 节点管理和独立 Excel / BPS 功能各自使用原有设置。

## Mihomo 节点与固定代理

在代理管理中的 Mihomo 面板可单独检测节点连通性、查看质量报告、按国家和状态筛选，并将选中的节点添加为固定代理。固定代理绑定节点身份，不允许通过编辑地址改绑其他出口；节点或来源被删除、禁用后不会静默换到别的节点。删除固定代理时会同步停用本地监听，数据库删除失败则恢复绑定。

固定监听由已有托管 Mihomo 内核管理，使用 32000–41999 端口段；绑定文件以 0600 权限持久保存。需要由管理员在页面按需安装、启动内核和选择节点，本次代码合并本身不会启动内核。

## 780 票据采集与验收

780 票据需要完成两次短请求：首次获取完整票据，随后携带同一票据和路由 Cookie 续接；两次流必须正常结束，续接不能换票或更换路由。长度、分块形状以及 Cookie 声明的 host 仅作为检查信息，不再单独认定票据质量。

采集结果区分换票、换路由、请求未完成、模型声明不匹配、限流等原因。手动采集的换节点策略以验收失败为依据，旧的 `312_only` / `312_or_2fail` 设置读取后会转换为新的策略。已有 292 等非 780 票据沿用原有身份固定规则。

## SSE 快速复用

在打票管理的「Astra 快速复用」中选择互不重叠的来源账号和目标账号并保存。来源优先使用已入库的有效 SSE 票据；缺票时由现有采集器自采。目标账号使用自己的授权，在来源票据的固定出口完成两次请求，验证通过后保存目标自己的完整票据与出口信息。失败后不会把来源票据复制为目标票据。

保存启用配置会自动准备来源并逐一验证目标，会使用模型请求额度。可在运行状态里查看准备阶段、目标票据剩余时间，以及手动执行来源准备或目标验证。业务请求只消费已入库票据，缺票时按既有门票策略处理，不在业务请求中现场采集。

复用当前支持 SSE。WebSocket 保持现有自采票据流程，历史 WS 固定会话和独立轮换 Cookie wrapper 未启用。原生 OAuth 账号额外持有 Excel grant 不会因此失去原生采集能力；主凭据本身属于 Excel OAuth 的账号始终不进入原生采集。

## 票池调度与观测

「号池调度」按自动采集范围内的实际有效票据每秒同步，可选择关闭/恢复账号调度、移除/恢复 Astra 模型、或加入/移出指定分组。模型模式只读 Astra 票据；分组模式保留原优先级、创建时间及未选中分组。恢复只撤销自身拥有的修改，检测到人工变更会停止覆盖。关闭接管后保持当时状态。

默认「仅可调度账号」采集范围仍会给票池调度自身暂停的账号补票，验收通过后自动恢复调度；它不会跳过账号状态、过期时间或冷却限制。由票池调度暂时移出的采集分组同样保留补票资格。票据入库、探测结果写入以及同一账号身份的 OAuth token 自动刷新不会误判为人工修改；管理员修改账号或分组后，后台不再覆盖该次人工决定。只走 BPS 的已配置模型不参与原生票池调度。

建议先保存自动采集范围并确认票据状态，再开启号池调度。若需要手动接管，先关闭号池调度，再恢复账号的调度开关、模型或分组；关闭开关本身不会批量恢复此前状态。

覆盖率每 5 秒采样，显示实际观测期间有票/缺票秒数；重启、范围变化或长采样间隔不会补算缺失历史。网关历史保存脱敏后的 host、账号组合、通过/失败计数和原因，不保存票据、Cookie 或代理密码。

可选的「糖果题观察」默认关闭。启用后，在成功业务流关闭并释放出口后，最多并发 2 个独立、有时限的观察请求；结果只用于展示，不影响原业务响应、票据有效性、账号调度或自动重试。

## 数据与验证边界

新增迁移为 `335_mihomo_static_proxy_bindings.sql`、`336_astra_gateway_history.sql`、`337_astra_scheduling_states.sql`，不改历史迁移。服务停止时会取消并等待自动准备、采样和调度任务退出。

本地单元测试、前端测试和 PostgreSQL/Redis 集成测试使用本地 mock/测试容器。它们不证明某个真实账号、节点或上游模型当前可用；真实状态由管理员保存配置后的准备流程和显式检测返回。

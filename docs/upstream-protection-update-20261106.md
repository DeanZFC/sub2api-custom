## 新增入口与行为

1. 账号列表「性能监控」：上游 HTTP 错误率上下限、独立暂停与解除、审计记录。默认关闭；统计周期默认 60 分钟，可在网关设置中调整。仅统计本进程通过共享 HTTP 传输收到的响应，非集群最终请求失败率。未接入本地不存在的 TPS / TTFT / 降智率保护采集链。
2. 分组管理 → 编辑 OpenAI 分组：「零缓存保护」，默认关闭，默认暂停 5 分钟。最近 20 条合格样本中至少 18 条零缓存时暂停该客户在已开启分组的新请求。未知缓存、媒体、未展开历史、未完成或中断输出不当作有效零缓存样本。零缓存是启发式信号，不是蒸馏认定。
3. Scheduler outbox：失败事件先持久化再推进主水位，带租约和 generation 的后台补偿；重试发布前在账号行锁内读取当前状态，防止旧事件复活已停用、迁移或删除的账号。
4. 上下文超限：明确的 context_length_exceeded 默认规范为 400；保留原始上游证据，运维列表、趋势与通道监控按客户请求限制分类，避免无谓冷却换号。
5. SSE / WebSocket 首字时间：排除元数据、空 delta 和仅终止事件，支持完整多行 SSE 事件；保持现有发送和重放边界。
6. API Key 并发占用统计：独立 TTL 和长请求续期；释放后幂等清理，过期/丢失槽位不会被续期复活。本地没有引入上游 API Key 排队调度系统。

## API Key TTL 配置与滚动升级

配置项为 gateway.api_key_slot_ttl_seconds；0 继承 gateway.concurrency_slot_ttl_minutes，本项目配置默认继承 30 分钟；显式正值至少 30 秒。心跳间隔为有效 TTL 的三分之一。它影响 API Key 活跃请求统计，不改变账号/用户槽位 TTL 或新增排队限额。

共享同一 Redis 的实例必须使用一致 TTL。变更 TTL 或从无心跳版本升级时，先停止新流量，等待相关长请求结束并确认槽位排空，再对全部实例更新配置和版本后恢复流量。不要在混用新旧 TTL 时清理共享槽位；旧读者使用短窗口可能删除新实例仍持有的长请求槽位。回滚同样先排空，保持统一配置。

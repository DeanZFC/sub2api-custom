# 会话换绑与缓存稳定性合并说明

日期：2026-11-10。目标分支：`sub2api-custom`。起始提交：`87eea4e9b9ebddd28298bc3bad0634736ba61aec`，版本保持 `v0.2.20-custom.6`。本次只移植会话换绑相关修改，不导入 ranxi 全部分支历史。

## 来源

- ranxi2001/sub2api PR #756：切换上游账号后更新会话粘性绑定。PR head：`b10b3856bee445820a7748764b9641f8229d3dbe`，merge：`7c337167324b7c53d27d050031d7d0dbcee27849`。
- ranxi2001/sub2api PR #757：legacy 候选通过外层准入后再发布会话绑定。PR head：`9d128f690043a9b2b6dccd077584b7acab63deec`，merge：`45e92f44470f91435bd261ea18111c271063c0ac`。

两项一起移植，避免仅合入 #756 后，不符合传输协议或端点能力的中间候选抢先写入绑定，导致最终候选无法换绑。

## 行为

- 普通会话因并发容量、首字延迟或错误率从 A 切换到 B 时，B 实际取得并发槽位且通过相应准入后，更新会话绑定；后续 A 恢复也不会仅因恢复而把会话拉回 A。
- 尚在等待槽位、选择失败、外层能力检查拒绝的候选，不提前发布新绑定。
- 将选号时观察到的绑定随等待结果传递；Redis Lua 原子比较并更新，防止旧等待者覆盖已经迁移的新绑定。
- 新旧会话键一起更新；关闭旧格式双写后清理旧键，避免旧键回退重新带回原账号。账号 ID 按字符串比较，避免 Lua 数值精度丢失。
- 该修复减少账号来回切换造成的上下文缓存波动，不保证具体缓存命中率；上游缓存仍受模型、提示词、请求格式、时效等因素影响。

## 定制兼容

保留原有质量指标暂停与试运行恢复、利润门、明确会话归属与 continuation、guardian、严格故障转移、图片尺寸路由、BPS 优先、打票准入和代理池并发逻辑。普通容量逃逸现在换绑；定制质量暂停等显式保留归属的场景继续遵循原策略。不会恢复此前移除的账号保护或分组零缓存保护功能。

本地不存在的 priority observation、OAuth RPM 80% 调度及无关 CI 工作流未导入。新增 legacy 准入测试使用现有排除账号路径覆盖相同换绑边界。

无需新增配置开关、数据库迁移或前端操作；更新后的后端部署并启动后，在已有会话粘性与调度配置下生效。

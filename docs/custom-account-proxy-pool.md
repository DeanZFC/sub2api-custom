# 账号多代理

账号创建、编辑、批量编辑支持选择多个代理。OAuth 认证使用列表中的第一个代理；账号保存后的业务请求由 Redis 在可用代理之间轮询分配。

- 不选代理：保持原来的直连逻辑。
- 选择一个代理：保持原来的 `proxy_id` 和账号级并发槽位逻辑。
- 选择多个代理：每个代理的并发上限等于账号配置的并发数。例如，3 个代理、账号并发 10，最多同时放行 30 个请求。一个代理满额时尝试下一个；全部满额时沿用现有等待或拒绝机制。
- 不改动官方的上游 429 响应、重试或额度行为。

## 一致性

Redis Lua 一次完成代理选择和并发占用，返回的代理 ID 决定请求副本的实际出口。释放函数始终释放该次请求的原槽位。各服务实例共用 Redis，因此并发限制和轮询游标跨实例生效。

WebSocket 后续轮次固定原出口，再次占用该出口的槽位；没有容量时沿用现有忙碌响应。共享的调度快照不会被请求修改。已停用或过期的代理不参与新请求分配，代理池不可用或 Redis 出错不会退回直连。

## API 与数据

创建接口使用 `proxy_ids: number[]`；更新和批量更新省略此字段表示不改动，空数组表示清空，一个元素表示回到单代理。继续支持旧客户端的 `proxy_id`：显式修改它会清除多代理绑定。列表与详情返回 `proxy_ids`，运行时列表额外返回 `proxy_pool` 中的代理名称和并发计数，不返回代理认证信息。

有序绑定存放于 `account_proxies`，迁移文件为 `240_add_account_proxy_pool.sql`。账号、绑定和调度通知在同一事务内保存。复制账号保留代理池，凭据影子账号继承母账号的代理配置。被池中账号使用的代理纳入引用计数，不能作为“未使用代理”删除。

## 验证

新增测试覆盖单代理兼容、跨实例并发、轮询、槽位释放和过期、WebSocket 固定出口、错误时不直连、绑定顺序及事务回滚。前端测试覆盖多选和单选交互，并验证创建、编辑、批量编辑以及列表更新。

后端完整测试中的 12 个已有失败已在修改前提交 `625c94430` 上复现，涉及 Codex 指纹、WebSocket 超时/失败转移和模型可用性测试；此次不改变这些功能。排除这组已确认的基线失败后，服务、仓库和处理器测试分别验证。
